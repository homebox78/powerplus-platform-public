## 3. 공통 계정·권한 (첫 작업)
- **users 하나**: `kind = staff | external`. **지금 파워플러스의 "solideos.com 만 로그인 허용"은 공용 서비스에서 푼다**(사용자 2026-10-06). solideos.com 은 차단 조건이 아니라 **staff 분류 조건** — 회사 메일로 OTP 인증하면 staff, 그 외는 누구나 OAuth 3종(구글·네이버·카카오)·이메일 OTP 로 가입해 external. 파워플러스 AuthService 의 `allowed_domain`·`open_until` 게이트는 이관하지 않는다(staff 판정 함수 하나로 대체).
- **플랜**: `staff`(전부 무료, 사내 전용 자산 포함) / `free` / `pro` / `team`. 홈박스 `Plan.php` 게이트를 공통 함수로 승격 — 모듈마다 `can(user, resource)` 한 함수만 부른다(G30 교훈: 출구마다 따로 걸면 샌다).
- **자산 공개 등급**(파워플러스 assets에 컬럼): `internal`(실제 제안서 장표 — 영구 사내) / `pro` / `free` / `public`. 홈박스 시안·갤러리도 같은 등급 축.
- **API/MCP 키**: 한 표(`api_keys`), 키 하나로 REST·MCP 둘 다, `scopes` 로 모듈 제한. 일일 한도·사용량 집계 공통(§10).
- 홈박스 `mcp_keys`·파워플러스 `mcp_keys` 는 마이그레이션 때 합친다.

## 4. 디자인 규칙 안내서 메뉴 (지금의 Solid Flow — 사용자 추가 지시)
- **성격(사용자)**: "일종의 디자인 규칙 안내서". 솔리데오 전용이 아니라 **SI 종사자 모두가 참고하는 공용 규칙**이므로, 현재 Solid Flow 의 CI 크림슨·솔리데오 표기·사내 스타터 킷 같은 회사 종속 요소는 걷어내거나 "예시 스킨"으로 내린다.
- **역할 두 가지**: ① 사람이 읽는 규칙(토큰·부품·KRDS 대응·접근성 체크리스트) ② 다른 모듈이 기계로 읽는 토큰 원본.
- **홈박스 키트(packages/kit, KRDS 77종 React·Vue)를 이 안내서의 재료로 삼을 수 있는지 검토**(사용자) — 둘 다 KRDS 원본에서 출발했고 부품 목록이 겹친다. 검토 기준: 토큰 체계가 하나로 합쳐지는가, 홈박스 MCP 조립이 깨지지 않는가, SSR·접근성 검사 결과가 유지되는가. 결과에 따라 "키트 = 안내서의 부품 카탈로그"로 합칠 수 있다.
- **플랫폼 외관은 홈박스가 베이스**(§0). Solid Flow 는 외관이 아니라 **콘텐츠**(사내 SI 프로젝트가 가져다 쓰는 규칙·토큰·부품)로 메뉴에 들어간다. 파워플러스(오렌지)·파워덱(오렌지 그라데이션)은 통합 틀(헤더·메뉴·계정) 안으로 들어오며 홈박스 톤으로 맞추고, 각 모듈 본문은 단계적으로.
- (§13.1 정정) 플랫폼 UI 토큰은 **홈박스**, powerGuide 가 배포하는 "SI 공용 규칙 토큰"은 별개 산출물. 홈박스 키트와의 통합은 P4 에서 검토 기준 3개로 실측 후 결정.
- 홈박스 MCP `get_design_system`·재현 묶음의 토큰 출력 형식을 Solid Flow 산출물 형식(CSS·Tailwind·Figma Tokens)과 맞추면 "레퍼런스 토큰 → 우리 디자인 시스템 형식"이 바로 된다.
- 메뉴 구성: 시작하기 · 토큰(색·타이포·간격·형태) · 부품 카탈로그(React/CSS 탭) · KRDS 대응표 · 접근성 체크리스트 · 다운로드(15종) · 변경 이력.

## 9. 관리자 모드 기획 (/admin — superadmin·admin·curator·support, §12.2)

## 10. API 통합 (사용자 2026-10-06 "되도록 API 는 한두 가지로 통합해서 설정·관리 쉽게")

지금은 모듈마다 API 와 키가 따로다: 파워플러스 `/api/*`+MCP(PHP 내장, mcp_keys) / 홈박스 `/api/*`+MCP(Node :3100, api_keys) / 파워덱 `/api`(worker_key·세션). **둘로 줄인다.**

| | 통합 후 | 하는 일 |
|---|---|---|
| **REST 하나** | `https://powerplus.solideos.com/api/v1/<모듈>/…` | 웹·애드인·엔진·외부 개발자. 프론트 컨트롤러 PHP 하나가 모듈로 분기. 인증 = 세션 또는 `Authorization: Bearer <키>` 한 가지 |
| **MCP 하나** | `https://powerplus.solideos.com/mcp` (= powerMCP) | AI 도구. 도구 이름은 모듈 접두(`assets_search`·`deck_convert`·`mock_get_replica_kit`·`guide_tokens`). 홈박스 MCP 의 Node 서버를 그대로 키우고, 파워플러스 PHP MCP 도구 7종은 이쪽으로 옮긴다 |

- **키 하나**: `api_keys` 한 표, 키 하나로 REST·MCP 둘 다. 키에 `scopes`(assets·deck·mock·guide)와 플랜·일 한도. 마이페이지 "API·MCP 키" 패널 하나, 관리자 "API·MCP" 메뉴 하나.
- **설정 하나**: 모듈별 config.php 세 벌 → `config.php` 하나(DB·SMTP·OAuth·토스·OpenRouter·Higgsfield). 관리자 설정 화면이 키 "있음/없음"만 보여 준다.
- **응답 규약 하나**: `{data, total, page, limit}` / `{error, code}`(PATTERNS 기본 포맷), 날짜 ISO, 출처 필드는 powerMock 규칙 그대로.
- 옛 주소 유지: `/powerPlus/api/*`·`/homebox/api/*`·`/homebox/mcp`·`/powerPlus/mcp` 는 **301 또는 프록시**로 당분간 살려 둔다(애드인 12명·외부 MCP 키 사용자).
- 이에 따라 **P7 통합 MCP 는 "마지막에 고민"이 아니라 P2 껍데기와 함께 시작**한다 — 처음부터 하나로 만드는 게 나중에 합치는 것보다 싸다. 파워덱 엔진(윈도우 PC)도 같은 REST 키로 붙는다.
- 예외: 애드인은 Office 가 매니페스트 URL 로 작업창을 부르므로 정적 파일 경로(`/assets/addin/`)는 REST 와 별개 — API 는 같은 `/api/v1/assets/` 를 쓴다.

## 12. 결정 반영 (사용자 2026-10-06)

### 12.1 powerDeck 외부 개방 + 사내 전용 자료 구분
- 장표 변환은 **외부에도 연다**. 대신 자료마다 **공개 범위를 구분**한다.
- **공개 범위(visibility)는 자산만의 축이 아니라 플랫폼 전체 콘텐츠의 공통 축**으로 정의한다: `internal`(사내 전용 — 실제 제안서 장표·발주처 정보·사내 템플릿) / `partner`(협력사 — 선택) / `pro` / `free` / `public`. 자산·장표 결과물·시안·갤러리·레퍼런스·가이드 문서 전부 이 한 컬럼.
- **기본값은 internal** — 올린 사람이 명시적으로 내려야 외부에 나간다(실수로 새는 방향이 아니라 실수로 안 보이는 방향). 사내 제안서 장표는 영구 internal, 낮추기는 admin 만.
- 외부 사용자가 올린 장표·파일은 **그 사용자 소유**(visibility `private` — 본인과 admin 만). 엔진은 **리눅스 서버 한 대**(PowerPoint 없이·OpenRouter 키 하나)에서만 처리한다. 외부 개방 전에 **처리 후 원본 보존 기간(현행: 완료 7일 뒤 맥락 자료 삭제)·삭제 요청 경로**를 약관에 둔다.
- `can()` 판정이 visibility × 사용자 kind·플랜 × 소유자 한 곳에서 끝난다. MCP 응답·검색·컬렉션·공유 링크 같은 **모든 출구**가 같은 함수를 지난다(G30).

### 12.2 역할 3종 + 슈퍼관리자
| 역할 | 누가 | 권한 |
|---|---|---|
| **superadmin** | **지정된 한 계정 고정**(코드 상수, 화면에서 부여·해제 불가 — 계정 값은 문서에 적지 않음) | 전부 + admin 역할 부여·회수, 설정·시크릿 상태, 감사 로그 열람, 점검 모드, 파괴 작업 최종 승인 |
| admin | superadmin 이 지정 | 사용자·등급·결제·모듈 운영 전부. superadmin 만 못 건드림 |
| curator | admin 이 지정 | 자산·검수·규칙 편집, 공개 범위 변경(internal 로 올리기만, 낮추기 X) |
| support | admin 이 지정 | 요청·제보·문의·공지 |
- `user_roles(user, role)` 복수 허용. superadmin 은 users.email 일치 + 구글 연결 검증(G29) 둘 다 만족할 때만 — 이메일만으로 승격 금지.
- 관리자 메뉴 노출도 역할별 `can()` 로. superadmin 전용 메뉴: 설정·감사 로그·역할 관리.

### 12.3 구독 플랜·포인트는 만들되 처음엔 숨긴다 (사용자 2026-10-06)
- **구독 플랜(요금제·결제·업그레이드 모달·크레딧)은 P2 에서 함께 제작**하되, **공개 플래그(`billing.visible`)를 꺼 두고 superadmin에게만 보인다.** 이유: "처음부터 유료 서비스를 보이는 건 좀 그렇다". 외부 사용자에게는 플랜 메뉴·Pro 배지·업그레이드 CTA·잠금 안내가 전부 안 뜨고, 그 자리는 "무료 기간" 또는 아무것도 없음. 플래그는 superadmin 설정 화면에서 켠다(켜는 순간이 P6).
- 플래그가 꺼진 동안 외부 계정의 플랜은 `free` 로 두되, 잠금(`can()`) 자체는 **그대로 동작**해야 한다 — 보이지만 않을 뿐 internal 자료는 못 본다. 숨김과 권한은 별개(G30).
- **포인트 체계**(홈박스 point_ledger 확장, 플랫폼 공통): 적립 = 가입·출석(일 1회 로그인)·생일(프로필 생일 입력, 연 1회)·공유(시안·컬렉션·가이드 공유 링크 열림)·시안 보관·좋아요 받기·글·댓글 / 사용 = 남의 시안 열람·pro 자산 1건 미리보기·장표 체험 1건 등 **유료 기능을 포인트로 맛보게**. 적립값은 홈박스 현행(가입 100·출석 5·보관 20·공유 50·좋아요 2·열람당 10·글 10·댓글 3)을 기본으로 두고 생일 50·공유 링크 열림 5(일 상한)를 추가 — 수치는 사용자 확정.
- 포인트는 플랜 플래그와 무관하게 **처음부터 공개** — 유료가 안 보이는 동안 참여 유도 장치는 포인트뿐이다. 마이페이지 "포인트" 패널(원장·적립 규칙·사용처), 관리자 "포인트" 메뉴(규칙 값 편집·수동 적립·부정 적립 감시: 같은 IP 다계정·일 상한).
- 중복 적립 차단은 홈박스 방식(UNIQUE user·reason·ref + 일 상한) 그대로.

   powerGuide 를 무료로 두는 이유: 이 플랫폼의 **외부 유입 입구**가 필요하고, 규칙 안내서가 가장 공유되기 쉬운 콘텐츠다.
2. **장표 변환은 원가가 있다**(OpenRouter·Higgsfield·엔진 PC 시간). 외부 개방이면 **크레딧 단위 과금**이 전제다 — 월 구독에 크레딧을 얹고 초과분 구매. 사내는 무제한이되 엔진 큐에서 **사내 우선**. 기획에 "크레딧" 개념이 없었다.
3. **온보딩·첫 화면이 없다.** 통합 홈이 "모듈 카드 4" 뿐이면 외부 방문자는 뭘 하는 곳인지 모른다. 홈 = 한 문장 정의("SI 실무자의 올인원") + 모듈별 "지금 바로 해 보기" 1개씩(자산 검색창·레퍼런스 검색·가이드 토큰 복사·장표 체험) + 로그인 유도. 홈박스 홈이 이미 "기관 목록 바로"인 것처럼 **첫 화면에서 바로 쓰게**.
4. **통합 검색이 없다.** 네 모듈이 한 사이트인데 검색이 모듈별이면 올인원이 아니다. 헤더 검색 = 자산·레퍼런스·가이드 문서·내 장표를 한 결과(탭)로. 홈박스 `/search`(Meili + SQL 폴백) 확장.
5. **법무·정책 페이지**: 약관·개인정보처리방침은 "명의 결정 뒤"로 미뤄져 있는데, **외부 업로드 파일(장표)·레퍼런스 캡처(관공서 저작물·공공누리)·AI 생성물 소유권·삭제요청(S16)** 네 가지는 명의와 무관하게 조항이 먼저 있어야 외부 개방이 된다.
6. **계정 병합 시나리오**: 파워플러스 OTP 사용자 12명 + 홈박스 OAuth 사용자 + 같은 사람이 양쪽에 있는 경우. 규칙: 회사 메일 OTP 로 로그인한 계정이 **기준(staff)**, 홈박스 소셜 계정은 "연결된 로그인"으로 붙인다. 병합은 본인이 마이페이지에서, 관리자 강제 병합은 감사 로그 필수.
7. **성공 지표(KPI)가 없다.** 모듈별 1개씩: 자산 = 월간 삽입 수·무결과율 / 장표 = 변환 완료율·재작업 횟수 / 목업 = 시안 첫 판정 평균점·게시 수 / 가이드 = 다운로드·규칙 제안 수 / 플랫폼 = 2모듈 이상 쓰는 사용자 비율(올인원이 성립하는지의 지표).
8. **알림·메일 경로**: OTP·장표 완료·결제 영수증이 SMTP 에 걸린다. 사내 서버 이관(P5) 전엔 Gmail 587, 이관 후 사내 릴레이 — P1 에서 추상화해 두지 않으면 두 번 짠다.
9. **공개 페이지 SEO**: powerGuide·powerMock 공개 목록은 검색 유입이 수익의 시작이다. 홈박스의 "PHP 가 index.html head 주입 + sitemap" 방식을 플랫폼 전체로.
10. **백업·복구**: 지금도 [제안] 상태. 외부 결제가 붙는 순간 의무가 된다 — P6 전에 확정.

### 13.3 위험
- **가장 큰 위험 = 사내 자료 유출.** 외부 개방·MCP·검색·공유 링크·갤러리·삭제요청 공개 로그 등 **출구가 열 곳이 넘는다.** §12.1 의 "기본값 internal + can() 한 곳" 을 코드 리뷰 체크리스트 1번으로. 출시 전 **외부 Free 계정으로 전 출구 실측**(시안 갤러리·공유 토큰·MCP 응답·검색 결과·RSS·사이트맵).
- **범위 팽창**: 네 모듈 재작성 + 계정 통합 + 결제 + 이관을 한 번에 하면 반년이다. **P1(계정)·P2(껍데기+powerMCP)·P3(공개 범위)까지가 "사내 출시"**, 거기서 멈춰 사내 사용자 12명으로 한 달 돌린 뒤 외부 개방(P6). 외부 개방 전 단계에 외부 기능을 섞지 않는다.
- **이름 충돌**: `powerPlus` 가 플랫폼 이름이면서 옛 애드인 이름 — 애드인 표기는 "powerAssets 애드인" 으로 바꾸되 매니페스트 이름 변경은 이관 때 한 번.

### 14.2 노출 제한 규칙 — 랜딩이 유출 출구가 되지 않게
- 모든 블록은 `can(user, asset)` 을 지난다. "최근 업데이트"는 **비로그인·외부 Free 에게 `public` 등급만**, Pro 는 pro 까지, staff 만 internal. 같은 쿼리를 등급별로 캐시(홈박스 데이터 판 캐시 방식) — 캐시 열쇠에 kind·plan 포함(안 그러면 staff 가 먼저 열어 채운 캐시가 외부로 샌다).
- **장표(ppt) 카테고리는 랜딩에서 기본 제외** — 실제 제안서 장표는 영구 internal 이고, 외부가 봐도 되는 장표가 생기기 전까지 블록 자체를 staff 전용으로.
- 썸네일·원본 URL 도 등급 밖이면 응답에서 빼고(null), 자리만 잠금으로. 공개 API(/api/public/assets 류)는 폐지하고 v1 + visibility 로 통일(지금 공개 API 는 "로그인 없이 전부"라 외부 개방과 정면 충돌).
- 숫자 블록은 사내 사용자 수·이메일·순위 같은 내부 지표를 외부에 안 보인다 — staff 에게만 상위 3명 78% 류.
- 출시 전 실측: 외부 Free 계정으로 /assets 랜딩·검색·세트·MCP 를 전부 열어 internal 0건 확인(§13.3 출구 실측에 포함).

### 14.3 staff 에게는 달라 보이는 것
- 히어로 아래 "내 즐겨찾기·최근 삽입" 바로가기(마이페이지 A04 와 같은 데이터), 사내 공지(자산 추가·장표 등록 알림).
- "최근 업데이트"에 internal 장표·제안서 낱장도 포함 — 사내 영업·제안 인력이 가장 자주 찾는 것.

### 14.4 다른 모듈도 같은 틀
powerDeck·powerMock·powerGuide 메뉴 첫 화면도 **랜딩 → 바로 해 보기 → 최근 업데이트 → 둘러보기** 같은 순서로 통일한다(홈 §13.2-3 과 한 문법). 모듈마다 "최근 업데이트" 원천: 장표 = 공개 허용된 변환 사례·업데이트 노트, 목업 = 새 게시 기관·갤러리 공유 시안, 가이드 = 규칙 변경 이력·새 부품.

## 16. 제작 방식 — 새 폴더 하나 + DB 재설계 (사용자 2026-10-06)

### 16.1 새 폴더 = 새 저장소
- 네 저장소(D:\powerPlus · D:\powerDeck · D:\homebox-handoff · D:\solideos)를 **참조 전용**으로 두고, **새 폴더 `D:\powerplus-platform`**(repo `homebox78/powerplus-platform`, private)에서 필요한 코드·데이터·자산을 **가져온다**(복사·이식). 기존 저장소는 운영 중이라 손대지 않는다 — 사내 출시(§13.4)까지 기존 서비스가 그대로 돈다.
- 모노레포(pnpm): `apps/web`(플랫폼 SPA, 홈박스 apps/web 을 뿌리로 복사) · `apps/addin`(파워플러스 애드인, 나중) · `apps/worker`(홈박스 수집 워커) · `engine/`(파워덱 리눅스 엔진) · `packages/mcp`(powerMCP) · `packages/shared`(taxonomy·zod·플랜 표) · `packages/kit` · `api/`(PHP 하나) · `db/`(새 스키마·시드·**옛 DB 이관 스크립트**) · `docs/`(이 기획·DB 설계서) · `mydev/`(myDev 서브모듈 — **첫 커밋 전에 init**, 오늘 파워덱 교훈).
- 가져오는 순서 = 단계 순서: 계정·플랜(홈박스 api/src/Plan·Session + 파워플러스 AuthService OTP) → 껍데기(홈박스 apps/web 레이아웃·hb 컴포넌트) → powerMCP(홈박스 packages/mcp + 파워플러스 McpServer 도구 7종) → 모듈별 API·화면.

### 16.2 DB — DBA 관점 재설계, 기존 스키마는 참고용
원칙: 기존 세 DB(powerplus 16MB·powerdeck·homebox 수십 테이블)를 그대로 붙이지 않는다. **새 스키마 하나**(MariaDB 10.11, utf8mb4_unicode_ci, InnoDB)를 설계하고 옛 데이터는 **이관 스크립트로 넣는다**. 옛 테이블은 설계 참고·이관 원천일 뿐.
- **이름 규칙**: 소문자 snake, 복수형 표(`users`), PK `id BIGINT UNSIGNED AUTO_INCREMENT`, 외부 노출 id 는 별도 `public_id CHAR(16)`(URL·MCP 응답에 숫자 PK 노출 금지 — 현 홈박스 `ref_id` 복제 사고 계열 차단), 시각 `created_at/updated_at DATETIME(3)`, 삭제는 `deleted_at`(소프트) + 90일 뒤 물리 삭제 배치, 예약어 식별자 금지(order·rank·key·cursor 교훈), 모든 FK 명시 + ON DELETE 정책 표기.
- **스키마 묶음(접두)**: `core_`(계정·권한·플랜·결제·크레딧·포인트·키·감사) / `asset_` / `deck_` / `mock_` / `guide_` / `comm_`(커뮤니티·알림). 접두로 모듈 소유가 보여 이관·덤프 제외(keep:always)·권한 리뷰가 쉽다.
- **공통 축 두 개를 처음부터**: ① `visibility ENUM(internal,partner,pro,free,public,private)` + `owner_user_id` 를 **콘텐츠 표마다**(asset_items·deck_jobs·mock_screens·mock_mockups·guide_docs…) — `can()` 이 읽는 유일한 축 ② `org_id`(회사·팀) — Team 좌석·사내(staff) 구분이 org 로 풀린다.
- core 표(초안): users · user_logins(provider,provider_uid,email_verified) · user_roles · orgs · org_members · plans · subscriptions · invoices · credit_ledger · point_ledger · point_rules · api_keys(scopes,module,limits) · api_usage_daily · admin_audit · settings(키=값, 시크릿은 암호화) · feature_flags(`billing.visible` 등) · notifications · removal_requests.
- 모듈 표는 옛 스키마를 **정규화 관점에서 손본다**: 파워플러스 `assets.tags`(JSON 문자열 LIKE 검색) → `asset_tags(asset_id, tag, lang)` + 사전 표(검색 정확도·대소문자 사고 해결) / 홈박스 `sections.structure`(JSON 26만 행, 덮는 인덱스로 버틴 것) → 자주 조회하는 값(제목·유형·좌표·크기)은 열로 승격, 나머지만 JSON / 파워덱 `job_events` 는 그대로(로그).
- **이관(db/migrate-legacy/)**: 모듈별 스크립트가 옛 DB 를 읽어 새 표에 upsert, **public_id 생성·visibility 기본 internal·owner 매핑**(파워플러스 OTP 사용자 12명 → staff, 홈박스 사용자 → external, 같은 이메일은 §13.2-6 규칙으로 병합). 멱등(3회 실행 수치 동일)·건수 대조표 출력. 옛 DB 는 읽기만.
- 성능·운영: 집계용 덮는 인덱스는 설계서에 쿼리와 함께 명시, 느린 쿼리 로그 켜기, 배포 `--db` 는 **폐지** — 새 플랫폼은 마이그레이션만 올리고 데이터는 운영이 원본(지금처럼 로컬 덤프로 운영을 덮는 방식은 keep:always 예외가 15개를 넘어 이미 한계).
- 산출물: `docs/db-design.md`(ER 그림·표 사전·FK·인덱스·이관 매핑) — **P1 코드 전에 사용자 검토**.

### 21.2 다음 단계 = P2 마무리 → 사내 출시 (권장 순서)
1. **운영 실데이터 이관**(가장 먼저 — 이게 없으면 사내 사용자가 들어와도 빈 집이다). 옛 DB 세 개(`powerplus`·`homebox`·`powerdeck`)가 같은 서버 MariaDB 에 있으므로 이관 스크립트를 **서버에서** 돌린다: 파워플러스 사용자 → staff(회사 메일), 홈박스 사용자 → external(같은 이메일은 §13.2-6 병합), 즐겨찾기·사용 기록·커뮤니티·시안·갤러리·포인트, 파워덱 작업. 멱등·건수 대조표. 옛 DB 는 읽기만.
2. **powerMCP**: 홈박스 `packages/mcp`(Node, 도구 22)를 옮겨 `powerplus.hom2box.com/mcp` 로(Apache ProxyPass, systemd). 도구 이름은 모듈 접두(`assets_`·`mock_`·`deck_`·`guide_`), 옛 이름은 별칭. 키는 `core_api_keys` 하나. 옛 `/homebox/mcp`·`/powerPlus/mcp` 는 당분간 유지.
3. **엔진 연결**: 구글 클라우드 파워덱 엔진의 접속 주소·워커 키를 새 REST(`/api/v1/deck/worker/*`)로 바꾼다. 판정 브라우저(시안 판정)도 같은 서버 워커로.
4. **출구 실측 `leak-audit`**: 외부 Free 계정으로 랜딩·검색·세트·저장 공유·갤러리·MCP·`/p`·sitemap 을 돌려 internal/pro 0건 — 사내 출시 필수 통과.
5. **관리자 모듈 화면**: 자산 공개 등급 일괄 변경(사내 전용 → 공개 판단이 여기서 일어남), 장표 작업·엔진 상태, 시안·갤러리 관리. + **통합 검색**(자산·가이드·내 장표·글을 한 결과 탭으로).
6. **사내 출시**: 임직원 공지 → 한 달 운영 → KPI 7종(§13.2-7) 측정 → 외부 개방 판단(P3).

뒤로 미루는 것: 와이어프레임(S4)·애드인 React 19 전환·결제(P6)·사내 서버 이관(P5, 사양 미정).

- **서버에 남을 것**: pptx 조립(마스터 고정 틀·서체 글줄 수치표·세로 가운데·고아 줄 보정·LibreOffice 렌더·자산 교체). 사용자 AI 는 **장표 명세 JSON**(와이어 좌표+글+자산 id+색 역할)만 보내고 서버가 결정적 코드로 조립 → `deck_render_pptx`(LLM 0, 렌더 CPU 만). 상자 종류별 pptx 그리기 함수는 새로 만들어야 한다.

- **다른 모듈**: powerAssets·powerGuide 도구는 LLM 과금 0, powerMock 서버 조립 도구도 결정적 PHP 라 0 — 실제 비용은 check_mockup 브라우저 렌더뿐. powerGuide 는 도구가 2개뿐이라 더 줄 것: guide_get_component(키트 77종 소스·사용법) · guide_search_rules(KRDS 지침) · 접근성 체크리스트 · guide_check_code(사용자 AI 코드를 토큰·대비·접근성으로 판정, 렌더 크레딧).
- **가이드·목업 합칠지 → 추천: 메뉴는 분리, MCP 재료는 한 정본.** 가이드 = 무료 유입 입구, 목업 = Pro 상품. 겹치는 건 토큰·부품뿐 → 가이드를 토큰·부품 정본으로, 목업 재료는 정본을 참조 id 로 싣는다.
- **과금 원칙**: 재료·결정적 판정(기획·와이어·대본) = 무료(Free 는 일 한도) / 렌더 판정·렌더 산출 = 크레딧. 남용 방지: 도구별 일 한도, 같은 token 은 edits 만, 같은 내용이면 이전 결과 재사용, 키당 동시 판정 1건, 크레딧 0 이면 막지 않고 요약판으로.
- **순서·합격 기준**: ① 와이어 재료·판정(packages/wire 공용, mock 와이어와 같은 엔진 — 웹 결과와 좌표 일치, LLM 0) ② 기획·대본 재료·판정(같은 원본 2종 수치 일치 90%+, 사용자 OK) ③ guide 확장·정본 참조(토큰 하드코딩 0) ④ deck_render_pptx(기존 엔진 결과와 나란히 사용자 OK, 넘침 0) ⑤ 시안(크레딧) ⑥ 과금·한도 ⑦ 웹·MCP 같은 JSON 형식.
- **위험**: 품질의 핵심은 "확정 시안을 그대로 pptx 로 옮기는" 에이전트 — ④가 못 미치면 "명세 + 서버 에이전트(높은 크레딧)" 혼합. 엔진을 새 REST 로 먼저 연결해야 한다.
