## 4. 반복되는 위반 패턴

1. **평가요소 문구가 제목에 안 들어간다**(8건 중 완전 통과 0). Muse 는 "사업 이해·추진 배경" 같은 일반 목차어를 쓰고, 평가 언급은 메시지 끝에 "…평가에 답합니다"로 붙이는 습관(옛 규칙 작업에서 두드러짐).
2. **배점 상위 3개 2장 이상 규칙이 5장 덱에서 불가능**하다. 5장이면 항목당 1장이 최대. 7건 중 6건이 5장(채팅·화면 기본값 또는 사용자 지정)이라 구조적으로 위반.
3. **발표 시간 → 장 수 규칙이 요청 장 수에 밀린다**(d1b9: 15분인데 5장). 경고도 없이 조용히 무시된다.
4. **첫 장표 수치 되돌려주기는 원자료에 수치가 많을 때만 지켜진다**(식약처·소상공인24 ○, 크레딧·MSP ✗). MSP·크레딧 context 에도 수치(장애 2시간·12시간 SLA, 12만 동시접속 등)는 있었지만 1쪽이 '필요성 서술'로 시작.
5. **표지 제목에 채팅 첫 말이 그대로 들어간다**(17b4·2cd4 — 채팅에서 시작한 작업).
6. **장 이름(section) 이중 표기**(82ed 6~27쪽).
7. 대본 규칙(PM 1인칭·블라인드·예상 질문·모호 표현)은 **대본 단계까지 간 Muse 작업이 없어 한 번도 검증되지 않았다.**

### 6.2 판정기 — 수치 대조 정규화(오탐 제거)

1. 숫자와 단위 사이 공백 제거 후 비교("24 개"→"24개"), **앞이 한글·영문에 바로 붙은 숫자(소상공인24, SFR-003)는 수치에서 제외**.
2. 퍼센트 정규화: "퍼센트"·"프로" ↔ "%".
3. 연도 정규화: "'14년"·"’14년"·"14년(문맥상 연도)" ↔ "2014년", "26년 10월" ↔ "2026년 10월".
4. 천 단위 구분: "2.400원"(원문 오기) ↔ "2,400원" — 소수점 뒤가 정확히 3자리이고 단위가 원·건·명이면 같은 값으로.
5. 연혁 숫자: "2019 건축행정…"처럼 연도 뒤에 바로 단어가 오는 연도는 단위 "건"으로 읽지 않기(연도 다음 공백+명사).
6. "원자료 수치 누락" 경고는 장 수 비례로: `min(누락, 장수 × 2)` 개까지만 세고, 핵심 수치 절에 있는 것만 대상(전체 숫자 X).
7. 덱 안 일관성 경고는 같은 단위 + 같은 대상 낱말(앞 2어절)이 같을 때만(“건당 5명/44명” 같은 다른 항목 오탐 제거).
8. 원자료가 context.md(요약)뿐이면 원문에 없는 숫자는 fatal 이 아니라 **info "원문 대조 불가"**로. 원 RFP 원문을 작업 폴더에 남겨 두면 그때만 fatal.

### 6.3 엔진 지침(design.py)

- **OUTLINE_SYSTEM**: "장 수가 규칙보다 적을 때의 우선순위"를 명시 — ① 첫 장표(발주처 수치) ② 배점 1·2위 항목 각 1장 ③ 나머지 묶음 ④ 마무리. 그리고 **장 title 또는 section 앞머리에 그 장이 답하는 평가 항목명을 원문 그대로** 쓰게 하고 예시 1줄("[기술 및 기능] 28만쪽 심사를 3개 축으로 줄입니다").
- **첫 장표**: "핵심 수치 절에서 2개 이상을 그대로" 로 정량화.
- **PURPOSE present**: 요청 장 수와 발표 시간이 어긋나면 기획을 그대로 진행하되 plan 에 `warnings: ["15분 발표 권장 12~15장, 요청 5장"]` 를 남기고, 화면·채팅이 이를 보여 주게.
- 메시지 끝에 "…평가에 답합니다"를 붙이는 습관 금지(제목으로 옮기라는 지시와 짝).

### 6.4 코드 버그

- 채팅 → design 작업 생성 시 표지 제목(title)에 첫 말이 들어가는 경로 수정: 프로젝트명이 비었으면 plan.title 을 쓰고, 요청 말투면 버린다.
- section 이중 결합("A · A · B") 원인 확인(옛 37장 작업 — 장 그룹 이름을 section 앞에 붙이는 단계).

### 6.5 대본 판정(checkScript) — 대본이 생기면 바로 쓰도록

- `pm-first-person`: 장마다 1인칭("저는·제가·저희") 비율, 3인칭 회사명 반복 경고.
- `blind`: context '발표 규정'에 블라인드 문구가 있으면 회사명(제안사명·로고 파일명)이 대본·장 글에 나오면 fatal, "저희 제안사" 사용 확인.
- `qa-coverage`: 배점 10점 이상 항목마다 예상 질문 1개 이상.
- BANNED_SCRIPT 에 context '표현 제한' 원문 낱말을 런타임에 합치기.

### 6.6 다음 검증

- 위 6.1·6.2 를 넣은 판정기를 같은 8건에 다시 돌려 오탐이 사라지고 실제 위반(평가 문구·배점 커버·첫 장표)만 남는지 확인.
- 장 수 10장 이상 Muse 작업 1건 + 대본까지 간 작업 1건을 만들어 ①②⑦⑧⑨를 실측(지금은 판정불가).
- 원 RFP 원문(docs)을 작업 폴더에 보존하는지 확인 — 없으면 수치 원문 일치는 영원히 요약본 대조에 그친다.
