# powerPlus 메인 채팅 설계서

- 작성일: 2026-10-08
- 문서 상태: 초안 (v0.1)
- 범위: 메인 화면에 넣을 대화형 작업창("메인 채팅")의 프로세스, 동작 범위, 기능, 등급별 한도, 서버 구조

> **표기 규칙**
> - **[확정]** 대화에서 결정된 사항
> - **[권장]** 제안 단계이며 아직 결정되지 않은 사항
> - **[확인 필요]** 실제 구현 상태를 확인해야 하는 사항

---

## 1. 개요

### 1.1 목표

사용자가 메인 화면의 채팅창에 "제안서 만들 건데 뭐부터 해야 하지?"라고 물으면, 채팅이 "우선 자료를 올려 주시면 검토해서 진행하겠습니다"라고 답하고, 그 뒤로 **자료 검토 → 기획 → 디자인 시안 → 결과물**까지 채팅 안에서 끊김 없이(논스톱) 진행되게 한다.

### 1.2 확정 사항

<표 1> 확정된 결정

| 항목 | 결정 |
|---|---|
| Jev 챗봇 | 지금의 간단한 도우미(도움말 안내) 역할 그대로 유지 **[확정]** |
| 메인 채팅 | 메인 화면에 GPT 창 형태로 추가, 제안서 작업을 논스톱 진행 **[확정]** |
| 사용 대상 | free 이상 회원 (팀원과 고객 모두) **[확정]** |
| free 범위 | 매달 기획 1장, 디자인 시안 1장 **[확정]** |
| pro 범위 | 그 이상 전부 **[확정]** |

### 1.3 두 채팅의 구분

<표 2> Jev 챗봇과 메인 채팅 비교

| 항목 | Jev 챗봇 (기존) | 메인 채팅 (신규) |
|---|---|---|
| 역할 | 도움말 안내원 | 작업 진행자 |
| 두뇌 | Jev (판단 전용, 글 생성 없음) | LLM (글 쓰는 AI) + Jev 보조 |
| 답변 | 사람이 미리 쓴 문구와 링크 | AI가 생성한 결과물 + 고정 안내 문구 |
| 대상 | 누구나 (IP당 시간당 60회) | 로그인 회원 |
| 위치 | 기존 위치 유지 | 메인 화면 중앙 |
| 비용 | 판정 1회 약 $0.00002 | 단계별로 LLM 비용 발생 |

## 2. 전체 구조

<그림 1> 구성 요소와 흐름

```
[사용자 브라우저]
   │  채팅 입력, 파일 업로드, 승인/수정 버튼
   ▼
[중간 서버]  ← 모든 판단과 통제가 모이는 곳
   ├─ ① 로그인 확인, 회원 등급 조회
   ├─ ② 한도 확인 (이번 달 기획/시안 사용량)
   ├─ ③ Jev 호출: 입력 분류 (승인 / 수정 / 새 요청 / 딴 질문)
   ├─ ④ 진행표에서 현재 단계 확인, 다음 동작 결정
   ├─ ⑤ LLM 호출: 글이 필요한 단계만
   ├─ ⑥ powerPlus MCP 도구 호출: 등급에 허용된 도구만
   └─ ⑦ 사용량 기록, 프로젝트 상태 저장
   ▼
[DB] 회원, 프로젝트, 단계 상태, 대화 기록, 사용량, 업로드 파일
```

### 2.1 설계 원칙

1. **겉은 채팅, 속은 진행표.** 자유 대화처럼 보이지만 내부는 정해진 단계를 따라간다. 현재 단계와 다음 할 일이 항상 분명해야 논스톱이 된다.
2. **통제는 서버가 한다.** 한도와 권한을 AI에게 말로 지시하지 않는다. 서버가 횟수를 세고, 허용되지 않은 도구는 AI에게 아예 넘기지 않는다.
3. **단계마다 승인을 받는다.** 방향이 틀린 채 끝까지 가면 전부 다시 해야 하고 비용도 낭비된다.
4. **AI 생성물과 고정 문구를 구분한다.** 안내, 한도, 오류 메시지는 미리 써 둔 문구를 쓰고, AI가 만든 결과물에는 표시를 붙인다.
5. **API 키는 서버에만 둔다.** 브라우저에 노출하지 않는다.

### 2.2 Jev와 LLM의 역할 분담

<표 3> 역할 분담

| 일 | 담당 | 비고 |
|---|---|---|
| 사용자 입력이 승인/수정/새 요청/딴 질문 중 무엇인지 분류 | Jev | 빠르고 저렴 |
| 작업 종류 분류 (제안서, 그 외) | Jev | 선택지에서 고르기 |
| 서비스 범위 밖 요청 걸러내기 | Jev | 확신이 낮으면 되묻기 |
| 자료 읽고 요약 | LLM | 가장 비싼 단계 |
| 목차, 기획, 원고 작성 | LLM | |
| 수정 요청 반영 | LLM | |
| 한도, 권한 판정 | 서버 규칙 | AI에게 맡기지 않음 |
| 안내, 한도, 오류 문구 | 고정 문구 | 관리자 화면에서 수정 |

Jev가 꺼져 있거나 실패하면 LLM이 분류를 대신하거나, 버튼 선택만으로 진행하게 한다 **[권장]**.

## 3. 메인 채팅 프로세스

### 3.1 전체 단계

<표 4> 단계 요약

| 번호 | 단계 | AI가 하는 일 | 사용자가 하는 일 | free | pro |
|---|---|---|---|---|---|
| 0 | 진입 | 인사, 시작 예시 제시 | 하고 싶은 일 입력 | O | O |
| 1 | 의도 파악 | 작업 종류 확인, 자료 요청 | 답변 | O | O |
| 2 | 자료 받기 | 업로드 안내, 파일 검사 | 파일 업로드 | 월 1건, 크기 제한 | O |
| 3 | 검토 | 자료 요약, 부족한 정보 질문 | 요약 확인, 보완 | O | O |
| 4 | 목차 | 전체 목차 제안 | 승인 또는 수정 | 제목만 | 전체 |
| 5 | 기획 | 장표별 기획 작성 | 승인 또는 수정 | 월 1장 | 전체 |
| 6 | 디자인 시안 | 장표 시안 생성 | 승인 또는 수정 | 월 1장 | 전체 |
| 7 | 원고 | 장표별 문구 작성 | 승인 또는 수정 | 잠김 | O |
| 8 | 결과물 | 전체 조립, 내보내기 | 내려받기 | 잠김 | O |

> 4단계의 "free는 제목만 보기"는 **[권장]** 사항이다. 전체 그림을 보여 줘야 잠긴 나머지가 pro 전환 동기가 된다.

### 3.2 단계별 상세

#### 0단계. 진입

- **화면**: 메인 중앙에 입력창. 아래에 시작 예시 버튼 ("제안서 만들기", "이어서 작업하기").
- **동작**: 진행 중인 프로젝트가 있으면 "이어서 하시겠어요?" 카드를 먼저 보여 준다.
- **비로그인**: 입력창은 보이되, 입력하면 로그인 안내를 띄운다. 입력한 문장은 로그인 후 그대로 이어 준다.

#### 1단계. 의도 파악

- **입력 예**: "나 제안서 만들 건데 뭐부터 해야 하지?"
- **동작**: Jev가 작업 종류를 분류한다. 제안서로 판정되면 고정 문구로 답한다.
- **답변 예 (고정 문구)**: "우선 자료를 올려 주시면 검토해서 진행하겠습니다. 제안요청서나 참고 자료가 있으면 올려 주세요."
- **자료가 없는 경우**: "자료 없이 시작" 버튼을 제공하고, 주제, 대상, 분량, 마감 등을 몇 가지 질문으로 받는다.
- **범위 밖 요청**: 서비스가 하지 않는 일이면 그렇다고 알리고 Jev 챗봇 또는 문의로 안내한다.

#### 2단계. 자료 받기

- **동작**: 파일 형식, 크기, 쪽수를 서버가 검사한다. 한도를 넘으면 고정 문구로 안내한다.
- **허용 형식 [권장]**: PDF, DOCX, PPTX, HWP/HWPX, TXT, 이미지.
- **화면**: 업로드 진행률, 올린 파일 목록, 삭제 버튼.
- **안내 표시**: 업로드 영역에 보관 기간과 "AI 학습에 사용하지 않음"을 명시한다.
- **free**: 월 1건, 크기 제한 **[권장]**.

#### 3단계. 검토

- **동작**: LLM이 자료를 읽고 핵심 요구사항, 평가 기준, 일정, 분량 조건을 요약한다. 빠진 정보가 있으면 질문한다.
- **결과 형식**: 요약 카드 (과업 개요, 요구사항 목록, 평가 항목, 주의점).
- **사용자**: "맞아요" 승인, 또는 고칠 점 입력.
- **저장**: 요약을 프로젝트에 저장한다. 이후 단계와 다음 달 작업은 원본 대신 이 요약을 재사용해 비용을 줄인다.

#### 4단계. 목차

- **동작**: LLM이 전체 목차(장표 제목과 한 줄 설명)를 제안한다.
- **free**: 제목만 표시, 설명과 세부는 잠금 표시 **[권장]**.
- **사용자**: 승인, 순서 변경, 장 추가/삭제 요청.

#### 5단계. 기획

- **동작**: 장표별로 핵심 메시지, 구성 요소, 배치 방향을 작성한다.
- **free**: 월 1장. 사용자가 목차에서 직접 고르거나, 핵심 장표를 자동 추천한다 **[권장]**. 표지처럼 가치가 낮은 장이 뽑히지 않게 한다.
- **pro**: 전체 장표를 차례로 또는 한꺼번에 진행.
- **결과 형식**: 기획 카드 (장 번호, 제목, 핵심 메시지, 구성 요소).

#### 6단계. 디자인 시안

- **동작**: 승인된 기획을 바탕으로 장표 시안을 만들고, 어울리는 powerAssets 자산을 추천한다.
- **free**: 월 1장. 5단계에서 기획한 그 장으로 이어 가는 것을 기본으로 한다 **[권장]**.
- **결과 형식**: 시안 미리보기 카드, 사용된 자산 목록, 크게 보기.

#### 7단계. 원고 (pro)

- **동작**: 장표별 본문 문구, 발표 대본을 작성한다.
- **free**: 잠금. 고정 문구로 pro 안내.

#### 8단계. 결과물 (pro)

- **동작**: 전체 장표를 조립해 내보낸다.
- **형식**: PPTX 기본, 그 외 형식은 **[확인 필요]**.
- **free**: 잠금. 단, free에서 만든 기획 1장과 시안 1장은 화면에서 계속 볼 수 있게 한다 **[권장]**.

### 3.3 진행표 (상태 전이)

<그림 2> 단계 이동 규칙

```
진입 → 의도 파악 → 자료 받기 → 검토 → 목차 → 기획 → 시안 → 원고 → 결과물
                      │           ▲      ▲      ▲      ▲      ▲
                      │           └──────┴──────┴──────┴──────┘
                      │              "수정 요청" 시 같은 단계 반복
                      └─ 자료 없이 시작 → 질문으로 정보 수집 → 검토

어느 단계에서든:
  - 딴 질문      → 답한 뒤 원래 단계로 복귀
  - 이전 단계로   → 해당 단계로 되돌아감 (뒤 단계 결과는 "다시 확인 필요" 표시)
  - 한도 도달    → 진행 멈춤, 고정 문구로 안내, 프로젝트 상태는 보존
  - 중단         → 상태 저장, 다음 방문 시 이어서 하기
```

<표 5> 사용자 입력 분류와 처리

| Jev 판정 | 처리 |
|---|---|
| 승인 | 다음 단계로 이동 |
| 수정 요청 | 같은 단계에서 다시 생성 (수정 횟수 차감) |
| 이전 단계 변경 | 해당 단계로 되돌아감 |
| 딴 질문 (서비스 관련) | 답변 후 복귀, 또는 Jev 챗봇 도움말 연결 |
| 범위 밖 | 하지 않는 일임을 알림 |
| 확신 낮음 | "승인 / 수정" 버튼으로 되묻기 |

> 입력만으로 판정하지 않도록 각 결과 카드에 **승인**, **수정 요청** 버튼을 함께 둔다. 버튼을 누르면 Jev 판정 없이 바로 처리된다.

## 4. 동작 범위

<표 6> 하는 것과 하지 않는 것

| 구분 | 내용 |
|---|---|
| 한다 | 제안서 작업을 자료 업로드부터 결과물까지 단계별 진행 |
| 한다 | 업로드 자료 검토와 요약 |
| 한다 | 목차, 기획, 디자인 시안, 원고, 내보내기 |
| 한다 | powerAssets 자산 검색과 추천 |
| 한다 | 프로젝트 저장, 이어서 하기, 이전 단계로 돌아가기 |
| 한다 | 등급별 한도 안내와 pro 전환 연결 |
| 하지 않는다 | 도움말 응대 (Jev 챗봇이 담당, 필요 시 연결만) |
| 하지 않는다 | powerPlus와 무관한 일반 잡담, 일반 지식 질의 |
| 하지 않는다 | 사용자를 대신한 외부 전송, 게시 (확인 없이) |
| 하지 않는다 | 다른 회원의 프로젝트나 자료 조회 |
| 추후 검토 | 제안서 외 문서 유형 (보고서, 소개서 등) |
| 추후 검토 | 크롬 확장 사이드패널, 파워포인트 애드인 작업창 탑재 |
| 추후 검토 | 채팅으로 powerPlus 전 기능 직접 실행 |

## 9. 비용 관리

- **가장 비싼 단계는 자료 검토다.** 결과물이 1장이어도 자료 읽기는 통째로 일어난다. free의 업로드 크기와 건수 제한이 핵심이다.
- **요약을 재사용한다.** 한 번 읽은 자료는 요약으로 저장하고, 이후 단계는 요약만 넘긴다.
- **분류는 Jev에 맡긴다.** 승인/수정 판정처럼 글이 필요 없는 일에 LLM을 쓰지 않는다.
- **버튼을 우선한다.** 승인, 수정 버튼은 AI 호출 없이 처리된다.
- **수정 횟수에 상한을 둔다.** 무한 수정은 1장 한도를 사실상 무제한으로 만든다.
- **한도 도달 시 LLM을 호출하지 않는다.** 고정 문구만 보낸다.
- **회원별 비용을 기록한다.** free 1인당 월 평균 비용을 실제로 재서 한도를 조정한다.
