> 분석 기준일: 2026-10-07. 개별 문서 상세 분석은 `부록_개별문서분석/01~07.md`, 추출 필드의 기계가독 정의는 `rfp_extraction_schema.json` 참조.

## 2. RFP 문서 구조 해부 — 어디에 무엇이 있는가

### 2.1 표준 대목차(IT 구축형, 전자정부지원사업·중앙부처 공통)
```
Ⅰ 사업 개요        추진배경·필요성 / 사업범위 / 기대효과            ← 니즈·수치 원천
Ⅱ 현황 및 문제점   업무현황 / 정보화현황(구성도는 대개 비공개) / 선진사례 / 문제점·개선방향 ← 사업이해도 장표 원천
Ⅲ 사업 추진계획    추진목표 / 추진전략 / 추진체계 / 추진일정 / 추진방안(입찰방식) ← 일정·거버넌스
Ⅳ 제안요청 내용    총괄표 → 목록 → 상세 요구사항(ID별) / 특수사항(감리·PIA·윈백·조견표) ← 문서의 50~70%
Ⅴ 제안서 작성요령  효력 / 작성지침·유의사항 / 제안서 목차 / 세부작성지침     ← 분량·형식·동영상 금지·모호표현 금지
Ⅵ 안내사항         입찰방식 / 평가방법 / 기술성 평가기준(배점표) / 제출서류 / 설명회 / 발표 규정 / 유의사항 / 상생협력
붙임              보안위규·위약금 / 적정사업기간 / 일반현황·실적 서식 / 기술적용계획표 / 하도급계획서 / SW영향평가 / 조견표
```
- **배점표가 본문이 아니라 붙임에만 있는 문서가 있다**(소상공인24 운영, 조폐공사, MPAS, 굿모닝 등). 붙임까지 파싱해야 한다.
- 발표 규정은 Ⅵ(안내사항)의 "제안 설명회", "입찰 시 유의사항", 그리고 Ⅴ(작성지침)의 "홍보용 동영상 금지"에 **분산**되어 있다.
- 효력 우선순위 조항("제안요청서 > 기술협상서 > 제안서 > 제안발표내용")은 Ⅴ-1 "제안서의 효력"에 있다.

### 2.2 유형별 변형
| 유형 | 구조 특징 | 파싱 포인트 |
|---|---|---|
| 운영·유지관리 | Ⅱ가 "유지관리 대상 현황"(장비·SW·메뉴 목록 수천 행)으로 비대. 요구사항은 MPR/MAR·MHR 중심. SLA 지표·장애 등급표가 QUR/PMR 또는 붙임에 존재 | 장비 수·SW 식 수·상주 인원·장애 복구시간·SLA 지표 추출 |
| 지자체(지방계약법) | 정량 20점(실적·신용·기술인력·사회적책임 감점형)이 본문 Ⅴ에 상세. 발표 규정은 "입찰공고문 참조"로 위임 많음 | 협상적격 "합산 70점" 확인, 지역제한, 사회적책임 감점 |
| 연구용역(국토부형) | 개요 → 과업내용(2~4쪽) → 과업수행지침 → 보고서·성과품 → 보안대책 → 작성요령 → 평가 → 선정 → 붙임 목차·서식. 과업은 짧고 지침·보안이 길다 | 연구진 등급(책임/연구원/보조원), 인력 수·경력 정량, 보안업무규칙 |
| 공단·공사형(KIND·KORAD) | 제안안내 → 일반사항 → 과업범위 → 작성요령 → 붙임 제출서류·평가기준. 발표 규정이 상세(시간·배석·신분확인) | 평가위원 수 구간표, 식별표식 감점 |
| 행사·연수·탐방 | RFP 본문 + 별도 **과업지시서** 첨부. 식순표(분 단위)·숙박·식사·교통·보험 조건이 과업지시서에 | 정량 조건(4성급·2인1실·45인승·보험 2억·KPI 80건) |
| 물품·설비(민간 발주, 정부지원사업) | 개요 → 규격표 → 참가자격 → 평가배점 → 작성지침 → 서식. 규격 적합성이 정성 최대 배점 | 규격 대조표 항목, 납기, 하자보증 연수, M&V |
| 2단계 경쟁(규격·가격 동시) | "규격 90점 통과 → 최저가". 감점·실격 조항이 매우 촘촘 | 작성지침 위반 감점표, 실격 사유 열거 |
| 입찰공고문 | 발표 일시·장소·시간, 동영상 삽입 금지, 자격, 제출 방법. **"공고서와 RFP가 다르면 공고서 우선"** | RFP와 병합 시 공고문 값이 우선 |
| 발주처 내부 사업계획서 | 목차에 "소요자원 및 예산", "성과계획서", "체크리스트"가 있으면 사업계획서. 예산 비중·성과지표·감사지적·로드맵 등 RFP에서 삭제되는 정보 보유 | 사업계획서 모드로 전환(6.6절) |

### 2.3 문서 역할 판별 규칙
1. 제목·표지에 "제안요청서/RFP/과업지시서" + 평가배점표 존재 → RFP
2. "공고 제○○호", 입찰 일정 중심, 배점표 요약만 → 공고문(RFP 보조, 값 우선)
3. "사전규격" → 공고 전 초안(발표 규정 대개 없음, 변경 가능)
4. "사업계획서" + 소요예산·성과계획서 → 발주처 내부 문서(니즈 보강용)
5. 동일 사업명 복수 파일 → 판본 식별(일자·사업금액·공고구분) 후 **최종 공고본**을 기준으로, diff를 기록(배점·첨부·자격·일정이 바뀜 — 12.3절)

## 3. 반드시 추출해야 할 필드(통합 스키마)

7개 묶음 분석에서 제안된 필드를 통합·중복 제거한 결과. 기계가독 정의는 `rfp_extraction_schema.json`. 열 "중요도"는 발표장표 생성에 미치는 영향(★★★ 필수 / ★★ 권장 / ★ 참고).

| 필드 | 설명 | 위치 | 예시 | 중요도 |

## 4. 발표(PT) 규정 패턴

### 4.1 발표 실시 여부 판별
| 판정 | 신호 문구 | 비율(46건) |
|---|---|---|
| 실시 | "제안 설명회", "제안서 발표", "프레젠테이션 평가", "PT ○○분", "발표자", "발표순서" | 약 60% |
| 조건부 | "발주기관에서 제안설명을 요구할 경우", "서면평가로 갈음할 수 있음", "조달청 일정에 따름" | 약 20% |
| 서면 | "서면평가", "서면심사를 원칙", "제출한 제안서로 평가" | 약 15% |
| 불명확·모순 | "서면평가" 명시인데 발표자료·발표 대리인 위임장 요구(현대차 EPC, 경상국립대 VR) | 소수 |

**키워드 오탐 주의**: "발표"는 "합격자 발표", "결과 발표", "우선협상대상자 발표", "발표자료(산출물)"로 쓰이는 경우가 많다. KOICA 채용솔루션 RFP는 "발표" 42회 중 40회가 채용 결과 발표였고 실제는 서면평가. **"제안 발표 / 제안설명회 / 제안서 설명 / 프레젠테이션 / PT평가 / 설명발표 / 발표자"를 조합해서 판정**해야 한다.

규칙: `pt_time_present`가 null이면 공고문을 찾고, 없으면 20분을 기본값으로 쓰되 "공고문 확인 필요" 경고를 출력한다. "제안사 수에 따라 조정 가능" 문구가 거의 항상 붙으므로 **15분 압축본**도 함께 설계하는 것이 안전하다.

### 4.3 발표자 규정(가장 강력한 규칙)
- 표준 문형(전자정부지원사업·중앙부처·공공기관 공통): **"제안 설명은 제안사의 사업관리자(PM)가 직접 발표하여야 하며, PM이 발표하지 않을 경우 발표 없이 제안서에 대한 서면평가로만 진행함"**. 근거는 「행정기관 및 공공기관 정보시스템 구축·운영 지침」 제20조.
- PM 요건이 함께 묶인다: 주사업자(공동수급체 대표사) 소속 임직원 / 입찰공고일 전일(또는 180일 전, 3개월 전)부터 제안서 평가일까지 계속 재직 / 사업기간 전담 상주 / 계약기간 중 교체 불가(동급 이상 예외) / 4대보험·재직증명·신분증·건강보험자격득실확인서 제출.
- 변형: "임원 또는 PM"(IBK 연수), "총괄책임자"(IBK 차량), "행사 실무책임자(중급 이상 기술자)"(항공안전의날), "공고일 기준 3개월 이상 재직 직원"(경북 전시), "업체별 사업 담당자"(테크노폴), "실제 연구를 수행하는 총괄 혹은 실무책임자"(경계선지능인).
- 불이익 수위: 서면평가(최다) → 정성평가 0점(경계선지능인) → 평가대상 제외(서울관광·한전기술) → 실격(경북 전시) → 핵심인력 역량 항목 한 단계 하향(KOICA). PM 이중표기·PMO를 PM처럼 기재 → 제안발표 제외(소상공인24 운영).
- **발표자 시스템 등록**: 나라장터 e-발주 제출 시 "제안발표 여부" 체크와 발표자 정보 등록이 필요(aT 화훼: 미등록 시 발표 불가).
- 배석 인원: 2인(인천·경계선·경북 전시), 3인(조폐공사·KORAD·메타버스), 4인(한전기술·캠코). 명시 없으면 3인을 기본으로.

**프로그램 함의**: 대본은 PM 1인 화법으로 작성하고, 발표 초반에 PM의 역할·경력·전담 의지를 짧게 담되(평가요소 "PM 전문성 및 재직기간 충족성"이 명시된 RFP 존재), 회사 홍보로 흐르지 않게 한다.

- 세부 배점이 5~8점으로 균등 분할된 표(소상공인24 운영)는 "누락 없는 전 항목 커버"가 전략, 10점 항목 8개(바우처)·10점 항목이 3개 이상(부담경감)이면 그 항목들에 장표를 집중.
- 동일 사업도 판본에 따라 배점 구조가 완전히 바뀐다(소상공인24 2차: 수행계획30/수행기반11 → 기술및기능25/성능및품질16, 장비 항목 삭제, 데이터5·운영5·테스트4·표준FW3 신설). 반드시 최종 공고본 기준.

## 6. 발주처의 진짜 니즈를 읽는 법

### 6.1 수치가 니즈다
발주처는 추진배경·현황·문제점에 **자기 문제를 숫자로** 써 놓는다. 이 숫자를 첫 장표군에서 그대로 되돌려주는 것이 사업이해도 점수의 핵심이다.
| 사례 | 발주처 수치 | 니즈 해석 |
|---|---|---|
| 홈택스 | 회원 3,717만·연 23억 방문·800여 서비스, 세무플랫폼 스크래핑 폭증 → 과부하 | 스크래핑 제어 + 집중기 무장애 + 수요자 중심 메뉴 |

### 6.2 연속사업 맥락이 니즈의 절반
- 분석 대상 IT RFP의 **대부분이 연속사업**(ISP→1차→2차→3차→운영, 1단계→2단계, 전년도 유지관리 재발주, '08 구축→'24 이관→고도화).
- 발주처 문구: "기 구축된 플랫폼의 모듈 구성을 이용 및 준용", "'24년 사업에 이어 잔여분 진행", "현 유지보수 사업단과 협업", "1차 산출물(표준화가이드·중계서버·테마) 적용", "차기 RFP 초안 작성 지원", "착수와 동시에 운영 지원".
- 함의: 전 단계 산출물을 아는 척이 아니라 **구체적으로 아는 장표**(모듈 매핑표, 1차→2차 비교표, 인수 체크리스트)가 차별화. 운영형은 "인수인계 공백 제로"가 최대 관심(인수인계 단독 10점인 RFP 존재).

| 보안특약·위약금 블록이 길고 등급별 금액이 명시(A급 2,000만원·3%) | 보안 사고 민감 → "전단계 보안" 전용 장표 + 누출금지정보 관리 계획 |

### 6.5 반복 키워드 → 핵심 메시지 어휘
RFP 전체에서 빈도가 높은 어휘를 뽑아 핵심 메시지 3개와 장표 제목에 **발주처 어휘 그대로** 쓴다. 예: "One-Touch, One-GOV", "누구나 쉽게, 한 곳에서 한 번에", "배움 없이도", "품격 있는 법정기념행사", "국민이 신뢰하는", "글로컬 인재", "서비스 모델 재설계", "1등급 정보시스템".

### 6.6 발주처 내부 사업계획서가 함께 있을 때
- RFP 대목차 1~4장은 사업계획서를 거의 그대로 옮기고, 5장 소요예산·성과계획서·체크리스트를 **삭제**한 뒤 작성요령·안내사항을 붙인 구조(소상공인24 2차 사례).
- 사업계획서에서만 얻는 것: 단위업무별 예산 비중(→ **발표 시간 배분 기준**, 예: 일괄신청 38%), 성과지표 목표치(→ 성과관리 장표), 감사원·국회 지적(→ 당위성 한 줄), 1차→2차 비교표·연도별 로드맵(→ 연속성·확장성 장표), FP 산정근거(→ 범위 통제 논리), 기대효과 산출식.
- 주의: 사업계획서 수치(총사업비 8,999백만, 6.5개월)와 RFP 수치(6,765백만, 190일)를 혼동하지 말고 RFP 수치를 쓴다. 인건비 단가·FP 내역은 발표에 노출하지 않는다.

## 7. 사업유형별 프로파일과 장표 템플릿

각 프로파일은 (a) 요구사항·배점 특징 (b) 핵심 메시지 패턴 (c) 필수 장표 시퀀스(괄호: 대응 평가항목) (d) 차별화 (e) 금기로 구성.

### 7.1 IT 시스템 구축·고도화(중·대형, 전자정부지원사업·중앙부처)
- (a) SFR 50~90개 + ECR/CSR/DAR/SIR. 기술 90:10, 85%, 차등 1.5~3점. 사업이해도 10·기능 10 최대. 조견표·기술적용계획표·하도급계획서 필수. 300p(150장) 권장. PM 직접 발표, 동영상 금지, 시간 미명시(공고문).
- (b) ① "전 단계를 이어받아 끝낸다"(연속성·정합성) ② "발주처 문제 수치를 해결하는 간판 기능"(원클릭 환급, 서류 0장 원스톱, 59종 연계) ③ "무장애·보안·일정을 숫자로 약속"(동시접속·응답시간·감리 3회·오픈일).
- (c) 15장 표준:
  1. 사업 이해 — 발주처 문제 수치·연차 로드맵에서 본 사업의 위치(사업이해도)
  2. 문제 재정의 → 개선방향 매핑(사업이해도 "문제파악의 정확성")
  3. 목표시스템 구성도 한 장(사업이해도 "목표시스템 구성의 적정성" — 세부작성지침이 명시 요구)
  4. 추진전략·위험 Top5와 대안(추진전략 "일정·위험요소 고려")
  5. 수행조직·컨소시엄 역할·중소기업 지분·전 단계 사업단/현 운영사 협업(추진체계·상생협력)
  6. 개발방법론·단계별 산출물·감리 대응(개발방법론·일정)
  7~9. 핵심 기능 3개 묶음(화면 시나리오·프로세스)(기능 10)
  10. 연계 매트릭스(기관·방식·난이도·일정)(인터페이스)
  11. 데이터 전환·표준화·검증·책임조직(데이터)
  12. 성능·테스트(목표치·도구·시나리오)(성능·테스트)
  13. 보안·개인정보 — 설계~검증 전단계, 시큐어코딩 도구·횟수, PIA, 누출금지정보 관리(보안·기밀보안)
  14. 일정 WBS·마일스톤·품질관리·인증(일정·품질)
  15. 교육·인수인계·기술지원·하자보수·안정화 + 하도급 "없음/10% 이하" 선언(프로젝트 지원·하도급)
- (d) 전 단계 산출물 매핑표, 연계기관 협의 경험, 발주처 도메인(세무·민원·소상공인) 실적, 솔루션 BMT 수치.
- (e) PM 외 발표, 홍보 동영상, 제안서와 다른 수치, "검토 가능" 표현, 1단계와 단절된 새 아키텍처, 분담이행 컨소시엄(공동이행만 허용 시), 장비 중심 설명(ECR 없는 사업).

### 7.2 IT 운영·유지관리
- (a) MPR/MAR 30~40개 + MHR(인력 등급·인원·재직·교체·병행근무) + SLA 지표표 + 장애 등급별 복구시간. 유지관리 수행 10·인력 10·SLA 10·인수인계 10·장애대응 8 등. 100~200p. 중소기업 한정·직접생산증명 많음. 하도급 불허 사례(청주시·인천).
- (b) ① "Day-1부터 공백 없는 운영"(사전 투입·인수인계·표준운영절차) ② "검증된 N명 상주팀"(등급·경력·4대보험·정규직·백업) ③ "장애 X-Y-Z시간과 SLA 지표를 숫자로 책임"(가동률·2h 도착·4h 복구·CSR 납기).
- (c) 13장 표준: 대상 시스템·자산 지도(이해도) / 운영 목표·KPI·SLA 제안값 / 추진전략(인수→안정화→개선, 병행사업 협조) / 운영방법론(ITIL·표준운영절차 8프로세스) / 상주조직 구성표(요건 대비 충족 매트릭스) + 백업·교체 규칙 / 장애 등급별 타임라인·비상연락망·재발방지 / 예방점검·백업·DR·성능관리 / 응용 유지관리·SR·기능개선 프로세스 / 연계 운영 / 보안 체계(SER 1:1) / 사업관리·보고(주/월) / 교육·기술이전·종료 인수인계 / 정량·하도급·상생 요약.
- (d) 동일 시스템 운영 경험·기존 인력 승계안, SLA 자발 상향, 분산장비 점검 실적, 취약시기(야간·공휴일) 대응 수치(MTTR).
- (e) 구축형 제안 재탕(개발방법론·데이터 전환 중심), 인력 요건 미달 조직표, 프리랜서·파견 인력, 하도급 전제, 홍보 동영상.

### 7.3 연구·자문·기획 용역
- (a) 요구사항 ID 없음. 과업 2~4쪽, 지침·보안·서식이 길다. 배점: 이해·핵심과제 15~30 / 수행방법·접근방법 20~35 / 조직·연구진 10~25 / 일정 / 결과활용·사후관리 5~30 / 추가제안. 정량은 연구인력 수·평균경력·PM 건수·신용. 50p 내외(국토부형은 아래한글 13~14pt 지정). PM 직접 발표 20+10 또는 조건부. 블라인드 다수.
- (b) ① "발주처의 정책 맥락·법령·쟁점을 정확히 짚은 핵심 질문" ② "작동하는 방법론 프레임과 대안 비교(2안 이상)" ③ "보고서 이후 정책 반영·예산심의 대응까지 책임(사후관리)".
- (c) 12장 표준: 배경·정책 맥락·기존 연구 한계(이해도) / 핵심 질문·핵심과제 도출(이해도) / 과업↔산출물 매핑·RFP 부합 매트릭스 / 분석 프레임 전체도(접근방법) / 조사 설계(설문·FGI·사례·데이터 소스) / 대안 설계·비교평가 틀 / 독창적 아이디어 / 일정·마일스톤·보고(착수 10일·중간·최종 15~30일 전) / 연구진·자문위원 프로필(등급·경력·자격 충족표) / 품질·보안(국토부 보안업무규칙 등) / 결과 활용·후속지원 계획 / 기대효과.
- (d) 해당 분야 정책 네트워크·훈령 작성 경험, 계량 모형, 수용성 조사 경험, 영문 산출물(해외).
- (e) 자격 미달 책임연구원(평가 제외), 자문위원 "섭외 예정", 추상적 표현(감점), 수용여부 참조표 누락, 공동수급 불허 사업에서 컨소시엄 전제.

### 7.4 행사·홍보·연수·탐방·센터운영
- (a) RFP + 과업지시서(식순표·숙박·식사·교통·보험 조건). 80:20, 지방계약법이면 합산 70점. 이해도 10~20 / 기획·창의성 10~25 / 운영·실행 20 / 안전·비상 5~10 / 인력 10 / 관리·예산 10. 정량: 행사인력 수·팀장급 연차·재무비율·사회적가치 가산점. 발표 15~20분, 블라인드 표준, 동영상은 홍보영상 사업만 허용. 공동수급·하도급 불허 많음.
- (b) ① "발주처 어휘로 정의한 콘셉트·슬로건·스토리"(품격·추모+다짐, 글로컬, 온택트) ② "분 단위 운영 설계와 실명 인력(MC·가이드·출연진·자문단)" ③ "안전·비상·Plan B를 업체가 흡수"(기상악화 대체행사, 결항 대안, 보험 상향).

- (d) 동일 발주처·동종 행사 실적, 영상 샘플(허용 시), 현지 파트너(해외), 정량 조건 초과 충족(4성급→5성급, 보험 2억→상향).
- (e) 회사명·임직원 성명 노출, 전년 복제, 축제 톤(추모 행사), 관광 위주 일정(탐방), 환율 조건부 가격, 출연자 "협의 중".

### 7.5 물품·설비·EPC·CM·전시
- (a) 규격표가 요구사항. 정성 최대 = 규격 적합성(20)·성능·M&V(15)·일정·리스크(15). 정량 20~50(실적·신용·인력). 0점 트리거 존재(납기 공문·하자 3년). 2단계 경쟁(전시)은 규격 90점 통과 후 최저가라 감점·실격이 촘촘. 서면평가도 많음(제안서=발표자료).
- (b) ① "요구 규격을 항목별로 충족·상회(대조표)" ② "납기·시운전·검증(FAT/SAT/M&V) 일정의 현실성" ③ "하자·AS·예비품·교육과 별도 공사와의 인터페이스".
- (c) 11장 표준: 사업 이해(기존 설비 현황·교체 효과) / 규격 대조표(요구 vs 제안, 근거자료) / 핵심 성능 보증표·절감량 산출 / 구성도·배치도·동선 / 제어·연동·모니터링 / 제작·설치·시운전 일정 + 납기 공문 / 검수·성과검증(M&V) 계획 / 별도 공사 협업·간섭 해결·안전 / 인력·조직(기술사·기사) / 하자보증(연수 명시)·AS 대응시간·예비품·교육 / 실적·신용·안전보건 서약.
- (d) 동종 납품 실적(톤수·금액 기준 충족), 제조사 공식 협력 근거, 레퍼런스 BMT 수치.
- (e) 규격 미충족 항목 누락 기술, 사양 미명시, 하자보증 연수 미기재(0점), 납기 공문 누락(0점), 공동수급·하도급 언급(불허 사업), 추정가격 초과.

### 7.6 소규모(1억 미만)·소액
- 발표 규정이 없거나 서면인 경우 많음 → 제안서 요약 장표 10~12장. 정량 비중 20점. 공동수급 불허·직접생산증명·소기업 한정 흔함. 요구사항 누락은 "제안하지 않은 것으로 간주". 평가항목이 타 사업 템플릿 복붙인 경우(VR 구축에 "강사 섭외·홍보" 항목) "해당 없음" 대신 사업 관점으로 짧게 대응.

## 8. 발표장표 설계 규칙(프로그램용)

### 8.1 장표 수 산정
| 발표시간 | 본문 장표 수(표지·목차·마무리 제외) | 장당 평균 |
|---|---|---|
| 10분 | 8~10 | 60~70초 |
| 15분 | 12~15 | 60~70초 |
| 20분 | 15~18 | 65~75초 |
| 25~30분 | 18~24 | 70~80초 |
- `pt_material_spec`에 분량 상한(20p·30p·A3 30p)이 있으면 **그 상한이 우선**이고 표지·간지 포함 여부를 확인(aT: "표지·간지 제외 30p, 한 페이지 내 분할 금지").
- "제안사 수에 따라 조정 가능" 문구가 있으면 15분 압축 버전(핵심 10장)을 별도 산출.

### 8.2 배점 비례 배분
1. `score_table`에서 정성 항목만 추출(정량·가격·하도급·상생은 "확보 선언" 1장으로 묶음).
2. 각 대항목 배점 비율 × 본문 장표 수 = 장표 수(반올림, 최소 1장).
3. `top_weight_items` 3개는 각 2장 이상 확보.
4. 단일 10점 이상 항목(사업이해도·기능·운영·SLA·수행방안)은 "평가요소 문구를 소제목으로 쪼갠" 다층 장표로.
5. 사업계획서가 있으면 단위업무 예산 비중을 보조 가중치로 사용.

### 8.3 표준 장표 시퀀스(모든 유형 공통 뼈대)
```
[0] 표지(블라인드면 사업명·"제안사"만)        [1] 목차 = 평가항목 순서 + 조견표 매핑(장표번호↔평가항목↔제안서 쪽)
[2] 사업 이해 ①: 발주처 수치·법령·연차 맥락    [3] 사업 이해 ②: 문제 재정의 → 개선방향 → 목표(목표시스템 구성도)
[4] 추진전략 + 위험 Top5·대안                [5] 추진체계: 조직·PM·컨소시엄 지분·협력기관(상생 선언 포함)
[6~N-5] 평가표 순서대로 수행계획/기능/성능/데이터/보안/인력/SLA/운영 (배점 비례)
[N-4] 일정·마일스톤·품질                     [N-3] 프로젝트 지원(교육·인수인계·기술지원·하자·비상)
[N-2] 사후관리·결과활용·추가제안(자부담 출처 명시) [N-1] 정량·하도급·상생 "만점 근거" 요약
[N] 마무리: 핵심 메시지 3개 재진술(새 약속 금지)
```
- 목차 장표는 **조견표형**으로: 평가항목 → 발표 장표 번호 → 제안서 페이지. e-발주 조견표 기능·"평가항목별 조견표 제출 의무"와 정합.
- 첫 장표군은 회사 소개가 아니라 사업 이해(회사 소개는 금지되거나 10% 이내 권장, 블라인드면 불가).

### 8.4 장표 ↔ 제안서 ↔ 평가항목 매핑 의무
- 모든 장표에 `maps_to: {eval_item, proposal_section, proposal_page, requirement_ids[]}` 메타를 부여한다.
- 제안서에 없는 내용은 장표에 넣지 않는다(효력 최하위·상이 시 명기 의무·지침위반). 부득이하면 "제안서 ○쪽 보완 설명" 표기를 넣어 `pt_equals_proposal` 규정을 충족.
- 요구사항 ID 매핑 장표 1장(요구사항 수용 조견표 요약)은 IT 사업 필수.

## 9. 발표 점수를 가르는 핵심 포인트 TOP 15(통합)

1. **PM(사업책임자)이 직접, 요건을 갖추고, 정해진 인원·시간 안에서 발표** — 위반 시 발표 점수 자체가 사라진다(서면평가·0점·제외·실격). 재직·4대보험·신분증·시스템 발표자 등록까지 체크. [거의 전 문서]
2. **발표자료 = 제출 제안서(요약서)** — 수정본·추가 내용 금지, 상이 시 명기, 효력은 발표내용 최하위. 장표마다 제안서 쪽수 매핑. [전자정부지원·공단·금융·지자체]
3. **장표 목차 = 평가 배점표 순서, 조견표형 목차** — 평가위원이 점수표를 들고 듣는다. 지정 제안서 목차와 배점표가 1:1인 RFP가 대부분. [IT 전반, 비IT 다수]
4. **사업이해도(최대 단일 항목)는 발주처 수치·법령·연차 맥락의 정확한 재진술로 득점** — 53% 미신청, 56.8% 오프라인, 766대, 60톤, 항공안전법 6조의2. [전 문서]
5. **목표시스템 구성도 한 장** — "목표시스템 구성의 적정성"이 사업이해도 평가요소에 명시, 세부작성지침이 요구. [IT 구축]
6. **최대 배점 항목에 장표·시간 집중, 평가요소 문구를 소제목으로** — 기능 10, 운영·유지관리·SLA 각 10, 수행방안 20~35, 기획구성 20~25, 공사 요구사항 20, 수조 설치 10. 동점 처리도 배점 큰 항목 우선. [전 문서]
7. **숫자로 약속하는 성능·SLA·일정** — 동시접속 5만/12만·3초, 장애 4-8-12-24h, 가동률 99.8%, 2h 도착 4h 복구, 감리 3회, 오픈 7.14. 모호 표현은 불가능 간주. [IT·물품]
8. **인력의 실재성과 질** — 등급·경력·자격·4대보험·정규직·전담률·백업·외부 전문가 실명(박사급 2인, 변호사·변리사·회계사·노무사 각 1인). 정량(인력 수·연차)과 정성(구성 적정성)이 동시에 걸림. [운영·연구·행사]
9. **연속사업 맥락과 전 단계 산출물·현 운영사와의 협업·인수인계 공백 제로** — "기 구축 모듈 준용", "착수와 동시에 운영 지원", 160시간 병행근무. [IT 전반]
10. **연계·데이터·보안의 '검증 절차'와 '전단계 고려'** — 기관별 연계 매트릭스, 이관·정합성 검증·책임조직, 시큐어코딩 도구·횟수, PIA, 누출금지정보 관리, 보안위약금 인지. [IT]
11. **안전·비상·Plan B 전용 장표(비IT)** — 기상악화 대체행사, 결항·우천 대안, 낙오자·사고, 보험 상향, 서버 셧다운 방지·모의테스트. 배점 5~10이지만 등급 차이가 크다. [행사·연수·탐방·채용]
12. **정량·상생·하도급 점수의 사전 확보를 한 장에** — 중소기업 지분 50%↑, 하도급 없음/10%↓+표준계약서 만점, 실적 비율·건수, 신용등급, 국산제품 계획서, 4대보험 완납. [전 문서]
13. **0점 트리거·감점 요소 제거** — 납기 공문·하자 3년 미기재 0점, 신용등급 미제출 최하점, 식별표식 -3, 실적 3건 미만 자격 미충족, 퇴직자 고용확인서 미제출 탈락, 작성지침 위반 건당 1점. [10장 체크리스트]
14. **사후관리·결과활용·추가제안으로 마무리** — 연구·자문은 15~30점, 운영은 기술인계 10, 물품은 AS·예비품 10. 추가제안은 자부담 예산 출처·산출물·목표치 명시(없으면 평가 불가), 유료 SW/HW 추가제안 불인정. [전 문서]
15. **형식 준수** — 블라인드, 분량 상한(초과 시 발표 불가·채점 제외), 동영상 금지, PDF 1파일·용량, 제출 경로(나라장터·USB·이메일), 글꼴 포함, 발표자 등록, 시간 조정 대비 압축본. [전 문서]

## 10. 감점·실격 자동 검수 체크리스트

### 10.1 발표 전 필수 확인(생성 결과물에 대해)
- [ ] 발표자 = 제안서 명시 PM/사업책임자, 재직 요건·소속 요건 충족, 신분확인 서류 준비, 나라장터 발표자 등록 완료
- [ ] 배석 인원 ≤ `pt_attendees_limit`
- [ ] 장표 수·페이지 ≤ 분량 상한(표지·간지 포함 여부 확인), 한 페이지 분할 금지 준수, 판형(A4 횡/A3 가로) 준수
- [ ] `blind_rule`이면 회사명·로고·대표자·참여자명·사진·주소·이메일·파일명·메타데이터 전부 제거, 대본에서 회사명 발화 없음
- [ ] 동영상·애니메이션 임베드 없음(금지 시), 홍보·임원 인사 슬라이드 없음
- [ ] 모든 장표에 제안서 쪽 매핑 존재, 제안서에 없는 수치·약속 없음(있다면 "상이 사항 별도 명기")
- [ ] 대본에 "할 수 있다/고려/검토/가능하다/예정/추정" 표현 0건
- [ ] 15분 압축본 존재
- [ ] 발표자료 제출 시점·경로·부수·형식(PDF·PPT·USB·출력본·글꼴 포함) 확인

### 10.2 제안 내용 측면(장표에 반영되어야 할 "만점 근거")
- [ ] 하도급 계획: "없음" 또는 10% 이하+표준하도급계약서(해당 사업), 불허 사업이면 자사 100% 조직도
- [ ] 중소기업 참여 지분율 50% 이상(상생협력 정량)
- [ ] 국산제품 활용 계획서·기술적용계획표·조견표·자가진단표 등 미제출 시 최하등급 서식 제출 여부
- [ ] 납기(공문)·하자보증 연수·보험 금액 등 0점 트리거 항목 명시
- [ ] 투입인력 요건(등급·인원·경력·재직·정규직 비율) 충족 매트릭스
- [ ] 실적 정의(기간·단일 금액·동시 수행·업종) 충족 건수와 증빙
- [ ] 요구사항 전 항목 수용(누락은 "제안하지 않은 것으로 간주")

## 12. 한계·주의사항

### 12.1 "명시 없음"과 "불명확"의 구분
- 명시 없음: 문서에 규정이 없다 → 공고문·조달청 기본값으로 보완하고 "확인 필요" 플래그.
- 불명확: 문서 내 모순 또는 추출 손실 → 예: KEI "기술 85%" vs "합산 85점" 병존, 경상국립대 "68점" vs "76.5점" 병존, 현대차 "서면평가" vs 발표자료·위임장 요구, 솜밸리 배점표 합계 불일치, MPAS 별표 3점 vs 본표 5점, 한전기술 분량 수치 소실. 프로그램은 `ambiguity_flags[]`로 보존하고 보수적인 쪽(엄격한 쪽)을 기본 적용.

### 12.2 템플릿 잔재
- 발주처가 타 사업 RFP를 복붙한 흔적이 흔하다: 보안특약에 "외교부"가 남아 있음(중기부 사업), 운영사업에 구축형 배점표(데이터 전환·개발도구), VR 구축에 "강사 섭외·홍보" 평가항목, 운영지원 사업에 "하자보수 10점", 서면평가 사업에 PM 대리발표 불이익 조항, 제안서 목차 "준용" 문구만 있고 목차 표 없음.
- 대응: 평가항목 명칭을 그대로 믿지 말고 **사업 유형으로 재해석**해 채운다(개발방법론→운영방법론/SLA 체계, 데이터 전환→데이터 품질·정합성, 하자보수→안정화·장애 대응). 비어 보이는 항목도 "해당 없음"으로 두지 않는다(점수 항목이므로).

### 12.3 동일 사업 복수 판본
- 4쌍 비교 결과 바뀐 것: 사업금액(6,765→7,440백만), 배점 구조 전면 재편, 평가항목 신설·삭제(보안 5점 신설, 국산제품 삭제, 데이터·운영·테스트 신설), 제안서 보상(실시→미실시), 설명회 일자, 하도급계획서 서식(계약 시→입찰 시), 요구사항 신설(COR-010), 오픈일 확정 일정표 추가, 참가자격 문구 삭제.
- 규칙: 파일명·표지 일자·사업금액·공고구분·"(안)"·"수정"·"재공고"·"최종" 표기로 최신본을 고르고, 구판과의 diff를 사용자에게 보고. 특히 **배점표 diff는 장표 배분을 바꾼다**.

### 12.4 공고문 우선
- "입찰공고서와 과업내용서(제안요청서 등)의 내용이 서로 다를 경우 입찰공고서가 우선"(농식품부). 발표 일시·장소·시간·동영상 삽입 금지·제출 방법은 공고문에 있는 경우가 많으므로 RFP와 병합 시 공고문 값을 우선한다.

### 12.5 텍스트 추출 한계
- HWP/HWPX 표가 세로로 풀리거나 글자 순서가 깨질 수 있다(태광 PDF). 배점표·일정표·인력표는 표 복원 로직 또는 사람 검수가 필요. 시스템 구성도는 대개 "보안상 비공개(보안서약 후 입회 열람)"라 추출 불가 — 목표시스템 구성도는 텍스트 기반으로 재구성해야 한다.
