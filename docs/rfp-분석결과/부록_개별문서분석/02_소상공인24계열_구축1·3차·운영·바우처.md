### 3. 발표(PT) 규정
- 발표 실시 여부: **"사. 제안 설명회 개최 : 조달청 일정에 따름"** → 개최 시 PM 발표 의무.
- 원문 인용(유의사항):
  > "제안 설명회를 개최하는 경우 제안 설명은 제안사의 사업관리자(PM)가 직접 발표하여야 하며, 사업관리자(PM)가 발표하지 않을 경우 발표 없이 제안서에 대한 서면평가로만 진행함"
  > "사업관리자(PM)은 주사업자의 소속 근로자여야 하며, 제안서는 사업관리자(PM)가 직접 발표하여야 하고, 발주기관의 요청이 없는 한 사업관리자(PM)는 계약기간 동안 교체할 수 없음. … 교체를 요청하는 경우에는 제안서를 발표한 사업관리자(PM)와 동급이상의 경력과 역량을 보유한 자로 교체요청 가능"
  > "사업자가 제안서에 명시하여 계약의 내용을 구성한 사업관리자(PM) 및 투입인력에 관한 사항을 사업자가 계약대로 이행하지 아니하고 … 입찰참가자격 제한 처분을 받을 수 있음"
  > "발표내용이 제안서와 상이한 사항이 있는 경우 이를 별도로 명기하여야 함"
- 발표자료 관련: "제안 설명 시 **홍보용 동영상 활용 금지**"(5장 작성지침). 효력 우선순위 "제안요청서 > 기술협상서 > 제안서 > **제안발표내용**".
- 발표시간, 질의응답 시간, 장표 수 제한, 발표순서 결정방식, 평가위원 수, 장소/온라인 여부: **명시 없음**(조달청 규정·공고서 위임).
- 추가 규정: PM은 공동수급체 대표사 소속(PMR-001), 발표한 PM = 계약기간 내 교체 불가 → 발표자 선정이 곧 계약 인력 확정.

### 4. 평가 배점표

### 7. 발주처의 핵심 니즈·강조점
- **진짜 해결하고 싶은 것**: (a) 디지털 격차가 큰 소상공인(디지털 활용 가능 비율 15.4%, 전통시장 상인 50대 후반~60대)이 **"배움 없이도"** 지원사업을 찾고 신청하게 하는 것 — "능력 배양 교육 방식보다 배움 없이도 누구나 직관적으로 쉽게 쓸 수 있도록 지원하는 방식이 디지털 정보 격차 해소의 근본적인 해법". (b) 중기부·공단 47개 지원사업의 **채널 일원화 완성**(’22년 16개 → ’23년 11개 → ’24년 20개 = 3차에서 마지막 20개: 전통시장 화재공제 등 5, 소상공인 5, 지자체 10). (c) **지자체 수기 업무**(자격확인·중복수혜·정산·보고)의 디지털 전환과 다부처 정보 연계(정부24, 새올, e-호조, e-나라도움, 행정정보공동이용, 공공마이데이터). (d) 축적 데이터의 2차 활용 — **BI 시각화 기반 과학행정**, 데이터 개방 API.
- 반복 키워드: "한 곳에서 한 번에", "선제적·맞춤형", "지능정보 기반", "AI 이미지 판독", "원스톱 일괄신청", "디지털 격차 최소화", "과학적 행정", "데이터 표준화·품질관리", "국민비서", "소상공인마당→소상공인24 통합".
- 상위 정책·법령 근거: 디지털플랫폼정부 실현계획(국민드림 프로젝트, '23.4.14), 포스트 코로나 디지털 정부혁신 발전계획 2-2-6 소상공인 정책지원 서비스, 제2차 전자정부기본계획 1-4, 소상공인 보호 및 지원에 관한 법률 제21조, 전자정부법 제64조(전자정부지원사업).

### 8. 제약·자격·리스크
- 입찰참가자격: 국가계약법 시행령 제12조, 조달청 입찰참가자격등록, SW사업자(업종코드 1468) + 최근 결산 SW사업자신고확인서.
- 대기업 참여: 40억 이상 80억 미만 사업 → 매출 8천억 미만 대기업 참여 가능, 8천억 이상 대기업·상호출자제한기업집단 참여 불가. 단 "중소 SW사업자 참여지원 **예외 적용 인정 요청 예정**사업으로 인정 시 대기업 구분 없이 참여 가능"이라는 상충 문구 병존(불명확 — 공고서 확인 필요).
- 공동수급: 허용(공동이행), **5개사 이하, 구성원 최소 지분 10%**, 협정서 G2B 등록. 낙찰 후 구성원 변경 불가.
- 하도급: 사전승인, 50% 초과 불가, 10% 이상이면 공동수급체 구성, 적정성 85점 이상 승인, 재하도급 불허. 컨소시엄 외 인력은 하도급 간주.
- 상생협력: 중소기업 지분율 정량 5점 + 하도급 적정성 5점.
- 투입인력: PM은 **공동수급체 대표사 소속·전기간 투입·교체 불가**. 등급·자격증 요건은 명시 없음. 상용SW·외부 자문인력은 참여인력에서 제외하고 기재 금지.
- 준수 지침: 전자정부표준프레임워크(COR-003), 개방형 언어/표준 웹(COR-004), 공공기관 DB 표준화 지침(COR-009), 전자정부 웹사이트 품질관리 지침(COR-012), 웹접근성 고시(COR-013), SW개발보안 가이드(COR-014), SW사업정보 저장소 제출(COR-015), 과업심의위원회(COR-016), 전자정부지원사업 관리지침·운영지침·계약특수조건, 국가정보자원관리원 지침, CSAP 민간 클라우드.
- 지식재산권: 주관기관과 공동소유. 개발SW 타기관 공동활용 계획 없음.
- 특이: 보안특약 조문에 **"외교부의 보안정책"**이라는 타 기관 명칭이 그대로 남아 있음(복붙 흔적) → 질의 포인트.

### 9. 감점·실격·무효 조건
- PM이 직접 발표하지 않으면 발표 없이 서면평가(사실상 발표점수 기회 상실).
- 기술평가 85% 미만 → 협상적격 탈락.
- 제안서·발표에서 모호한 표현("할 수 있다" 등)은 "불가능한 것으로 간주".
- PM·투입인력 계약 불이행 → 입찰참가자격 제한.
- 부정당업자(입찰등록 마감일 기준) 참여 불가, 부정당 제재 중 업체와 공동수급·하도급 금지.
- 중소기업 지분 0% → 상생협력 0점. 하도급계획서 미제출/부적정 → 하도급 적정성 감점.
- 보안위규: 심각(비밀·개인정보 유출, 해킹, 결과물 유출) → 사업참여 제한·부정당업자 등록; 중대/보통/경미 → 보안위약금(계약금액의 3% / 1% / 0.5%, 상쇄·삭감 불가, 사업 종료 시 정산).
- 누출금지 대상정보(IP현황, 구성도, 계정정보, 취약점 결과, 소스코드 등) 유출 시 부정당업자 등록.
- 낙찰 후 컨소시엄 변경 불가, 제안서 반환 없음, 추가자료·현지실사 불응 불가.

### D. 발표 평가에서 점수를 가르는 핵심 포인트 TOP 10
1. **PM이 직접, 제안서와 일치하게 발표** — 미발표 시 서면평가, 상이 시 별도 명기, 발표내용은 효력 최하위 ([1][3][4][5] 공통 / [2] PM 이중표기 시 발표 제외).
2. **사업이해도(7~10점, 최대 단일 항목)**: 문제파악 정확성·목표시스템 구성도·RFP 부합성을 첫 장표군에서 숫자(15.4%, 53% 미신청, 1,032억 절감)와 함께 제시 ([1][3][4]).
3. **차등점수제(1.5~2점)로 기술 1위가 곧 낙찰** — 특정 항목 올인보다 전 항목 누락 없는 커버(특히 [2]는 5~8점 균등 배분) ([1][2][3][4]).
4. **모호 표현 금지 규정** — "검토하겠다/할 수 있다"는 불가능 처리 → 장표마다 수치·방식·산출물을 단정형으로 ([1][2][3][4]).
5. **요구사항 조견표/참조표** — 평가위원이 요구사항 충족 여부를 찾는 도구이므로 발표에서도 요구사항 ID 매핑 장표 1장 ([1][2][3]).
6. **연속사업 맥락 이해(ISP→1·2·3차→운영)와 기 구축 모듈 재사용 전략** — 3차는 "기 구축된 기능을 이용하여 추가 구현", 운영은 "현 유지보수 사업단과 협업"·고용승계 ([1][2]).
7. **인력 실재성**: PM 대표사 소속·전기간·정규직, 운영은 25명+ 역할별 경력, 상용SW·외부자문 인력 제외 — 조직도 장표에서 자격·재직 증빙을 명시 ([1][2][3][4]).
8. **보안·개인정보·법제도 준수의 구체성**: 시큐어코딩 진단도구·횟수, CC인증 EAL2, 개인정보 영향평가, 보안위약금 3% 규정 인지 — 보안 장표는 "전단계 고려 정도"가 평가요소 ([1][2][3][4]).
9. **데이터·연계 설계의 깊이**: 3차 데이터 요구 19개(이관·정제·정합성·공공데이터 품질평가), 운영은 데이터 요구 5점+인터페이스 6점, 바우처는 카드사·VAN·국세청 연계 — 연계 대상별 장단점 비교 표 ([1][2][3]).
10. **사업유형에 맞는 KPI 제시**: 구축은 일정·감리·성능 목표치, 운영은 SLA(가동률, 2h/4h 장애대응, CSR 납기 50점)·퇴사율, 바우처는 대량접수·24×365 — 평가항목 명칭이 구축형이어도 내용은 사업유형으로 재해석 ([2][3]).
