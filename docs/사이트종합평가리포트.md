## 3. 🟡 보통 – 전문가 관점 다듬기

### 3-1. 반응형·레이아웃
1. **홈 큰 제목 줄바꿈**: 모바일에서 "SI 실무자에게 필요한 것을 한 / 곳에." 처럼 단어가 끊김 → `word-break: keep-all` 적용(한글 서비스 전체 기본값으로 권장).
2. **관리자 화면 모바일 표**: 사용자·에셋·시안·문의 등 대부분의 관리자 표가 모바일에서 열이 좁아 날짜("2026.09.27 19:35")가 칸을 넘침. 관리자 화면은 모바일 우선순위가 낮더라도, 최소한 **표 가로 스크롤 + 첫 열 고정**은 필요.
3. **화면 높이 고정 화면**: `/mock/plan`, `/mock/mockups`, `/admin/contacts`, `/admin/requests`, `/admin/removals`, `/admin/policies`, `/admin/deck-settings/ref` 는 PC에서 화면 높이에 딱 맞춰 고정되는 구조. 목록이 많아지면 안쪽 스크롤이 생기는데, 스크롤 위치가 눈에 잘 안 띔 → 안쪽 스크롤 영역에 그림자/구분선 표시.
4. **관리자 메일 서식 화면**: 높이가 PC 11,749px, 모바일 20,692px 로 매우 김 → 서식별 접기/펼치기 또는 왼쪽 목록 + 오른쪽 미리보기 구조 권장.
5. **관리자 로그인 화면**: 오른쪽 그림이 상자 안에서 한쪽으로 치우쳐 잘려 보임(왼쪽 빈 여백). 그림을 `object-fit: cover; object-position: center` 로 정리.
6. **로그인 화면 로고 중복**: 상단 머리글 로고 + 로그인 상자 로고가 연달아 2번 나옴. 로그인·가입 화면은 머리글을 단순화하거나 상자 안 로고 제거.

### 3-2. 터치·클릭 영역
7. 목록의 **선택 상자(체크박스)가 16×16px** 로 매우 작음(관리자 표 전체, powerDeck 내 작업, API 키). 손가락 기준 최소 **44×44px** 권장 → 행 전체를 누르면 선택되게 하거나 누르는 영역을 넓힘.
8. 표 머리글 정렬 버튼 높이 23px, "개인정보처리방침/이용약관/사이트 로그인/문의하기" 같은 글자 링크 높이 14~18px → 모바일에서 누르기 어려움. 위아래 여백을 넣어 누르는 영역 32px 이상 확보.
9. 머리글 "⌘K" 표시와 모바일 하단 탭바 글자가 **11px** → 모바일 최소 12px 권장. 또 "⌘K"는 Windows 사용자에게는 "Ctrl K"로 보이도록 운영체제 구분 필요(대상 사용자인 공공 SI 실무자는 Windows 비율이 높음).

### 3-3. 접근성(이 서비스는 KRDS·접근성 가이드를 제공하므로 스스로 모범이 되어야 함)
10. **이름 없는 버튼**: 커뮤니티 "인기순" 켜고 끄기 스위치, powerDeck 작업 선택 상자, 관리자 AI 설정의 아이콘 버튼 5개에 이름(aria-label)이 없음 → 화면읽기 프로그램에서 "버튼"이라고만 읽힘.

## 4. 🟢 서비스 기획 관점 제안

1. **첫 화면의 첫 행동 명확히**: 홈에 AI 대화창·모듈 4개·숫자·MCP 안내가 모두 같은 무게로 나열됨. 처음 온 사람에게는 "제안서 장표 만들기" 같은 **대표 작업 1개**를 크게, 나머지는 그 아래로 위계를 주는 것이 전환율에 유리.
2. **비로그인 → 로그인 연결**: 비로그인 상태에서 AI 대화창이 보이지만 실제 사용 시 무엇이 막히는지 미리 알려주기("로그인하면 바로 결과를 저장합니다").
3. **모듈 이름의 이해도**: powerAssets/Deck/Mock/Guide 는 브랜드로는 좋지만 처음 온 공공 SI 실무자에게는 낯섦. 하단 탭바처럼 영문만 쓰지 말고 **"에셋 · 장표 · 목업 · 가이드"** 한글 보조 표기를 상단 메뉴에도 병기.
4. **요금·크레딧 투명성**: powerDeck 카드에 "$0.978 / $2.0" 처럼 **달러 원가**가 일반 사용자에게 보임. 사용자에게는 크레딧/원화로, 원가는 관리자에게만.
5. **관리자 대시보드 지표 정리**: 상단 모듈 카드(836, 30, 66, 37)와 아래 숫자 카드(46, 7,548, 30, 426)가 비슷한 내용을 다른 기준으로 반복. "오늘 처리할 일(문의 5, 삭제요청 1)" → "서비스 상태" → "추이" 순서로 **할 일 중심** 재배치 권장. 추이 그래프가 매끈한 산 모양 하나라 실제 데이터인지 의심될 수 있으니, 점 표시·값 표시 추가.
6. **관리자 메뉴 이름 일치**: 사이드바 "사용자·역할" ↔ 화면 제목 "사용자", "이력·과금" ↔ "장표 설정 · 이력 · 과금", URL `/account/settings` ↔ 화면 제목 "내 현황" 등 이름이 서로 달라 길 찾기가 헷갈림. 메뉴명 = 이동경로 = 화면 제목 = 탭 제목 통일.
7. **모바일 관리자 사용 범위 결정**: 관리자 화면을 모바일에서 어디까지 지원할지 기획적으로 정하고(예: 대시보드·문의 답변·삭제요청 처리만), 나머지는 "PC에서 이용해 주세요" 안내.
8. **없는 페이지(404) 개선**: 현재 탭 제목도 기본값이고 안내만 있음 → 검색창과 주요 모듈 바로가기를 함께 제공.
