# 오류 재발 방지 체크리스트

2026-10-11 저녁부터 10-12까지 커밋 63건을 다시 읽고 정리했다.
같은 종류의 실수가 두 번 나오지 않게, 사고마다 **원인 → 고친 것 → 막는 장치 → 확인 방법**을 적었다.
막는 장치는 둘로 나뉜다.

- **자동**: 배포 전 검사 `scripts/preflight.sh`가 막는다. 세 배포 스크립트 첫 줄에서 돈다.
- **규칙**: 기계로 잡기 어려워 사람(AI 포함)이 작업 전에 확인한다. `CLAUDE.md` "재발 방지 규칙"에 같은 번호로 있다.

새 사고가 나면 이 표에 한 줄을 추가하고 번호를 붙인다(지우지 않는다).
가능하면 `scripts/preflight.sh`에 검사를 하나 더하고, 표의 막는 장치를 "자동"으로 바꾼다.

## 3. 자동 검사 사용법

```bash
bash scripts/preflight.sh web       # api·apps·packages·db/migrations
bash scripts/preflight.sh mockref   # services/mockref-api
bash scripts/preflight.sh engine    # engine
PP_ALLOW_DIRTY=1 bash scripts/deploy.sh   # 커밋 안 한 변경을 정말 올려야 할 때만
```

- 클로저 검사에서 정말 의도한 줄은 같은 줄에 `// preflight-ok` 주석을 단다.
- 검사를 늘릴 때는 먼저 일부러 틀린 파일로 실패하는지 보고(음성 대조), 전체 코드에서 오탐이 0인지 본 뒤 넣는다.
