### C 정책 선택지 — 작업당 비용 한도(AiKeys::budgetGuard)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ① 지금대로 + 문구(적용됨) | 한 작업에 한 한도, 오류 글에 단계별 사용액 | 바꿀 것 없음, 총비용이 확실히 막힘 | 기획·시안이 길면 장표 단계가 시작부터 막힘 |
| ② 단계별 한도 | 기획·시안 한도와 장표 제작 한도를 따로(예: $2 + $3) | 앞 단계가 뒤 단계를 굶기지 않음 | 설정 칸 하나 더, deck_jobs 에 열(또는 opts) 추가 |
| ③ 장표 단계 진입 때 여유 보장 | 시안 확정(approveDesign build) 때 `budget_usd = max(budget_usd, spent_usd + 전역 한도)` | 코드 한 곳, 사용자가 확정한 것만 늘어남 | 총상한이 사실상 2배가 될 수 있음 |
| ④ 완성 뒤 부가 작업 제외 | 발표 대본·예상 질문(ask)은 월 상한만 보고 작업 한도는 보지 않음 | 다 만든 작업에서 대본이 막히지 않음 | 대본 비용이 작업 한도 밖으로 나감 |

추천은 ③+④ 입니다. 확정은 사용자가 해야 합니다.

**확정(2026-10-18 사용자)**: ③+④. 다만 ③은 한도 값을 키우지 않고 기준선(budget_base_usd)을 다시 잡는 꼴로 구현 — 관리자가 바꾼 한도(saveBudget)와 섞이지 않고, 총상한은 "확정 전 한도 + 확정 뒤 한도"로 정해진다.
