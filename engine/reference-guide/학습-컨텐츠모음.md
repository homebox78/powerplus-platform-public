# 실제 제안설명회 장표에서 배운 것

솔리데오 제안설명회 장표 540장(D 덱, 2026-01-16 컨텐츠 모음)을 한 장씩 보고 적은 기록에서 뽑은 규칙. 기획(장 나누기·message·scene·layout)과 시안 지시는 이것을 따른다.
번호는 `mockups/컨텐츠모음/NNN_*.jpg` — 참고(ref)로 쓸 때 `D123`. 유형별 전체 목록은 `mockups/CATALOG-D.md`.

## 1. 헤드라인 쓰는 법

실제 장표의 헤드라인은 세 가지 꼴이다. 장의 성격에 맞는 꼴을 고른다.

1. **약속문** — "…하겠습니다 / …합니다". 전략·수행 장의 기본. 주어 없이 동사로 끝낸다.
   - D203 업무 연속성(BCP)·재해복구(DRP) 등 비상대응체계를 강화하겠습니다 · D204 안정적 인수인계를 수행합니다 · D423 표준체계를 적용하고 이용현황을 관리합니다 · D120 민간 클라우드 구축을 제시합니다
2. **명사구 + 수식** — "무엇을 어떻게". 방안·절차·구성 장.
   - D023 위험·이슈 식별부터 대응, 모니터링까지 빈틈없이 관리 · D022 계획부터 종료까지 프로젝트 생애 전반의 품질관리 실시 · D080 분야별 전문 지식과 경험을 보유한 정예 인력 투입 · D396 정확한 특성 분석을 바탕으로 최적의 전략 마련
3. **질문·전환 한마디** — 흐름을 바꾸는 장. 짧게, 물음표나 느낌표로.
   - D089·D328·D387 "그런데 현실은?" · D329 "또 다른 현실은?" · D090 "그래서 시작 합니다!" · D027·D129·D379 "왜 솔리데오여야 하는가?" · D083 "제안사는, 다릅니다!"

규칙
- **수치를 헤드라인에 올린다.** D428 "190일+2개월 안정화까지, 매일 매일 차질없이" · D002 "함께 해온 25년" · D050 "2025년 SLA 평가 점수". 기간·횟수·점수·비율이 있으면 앞에.
- **범위를 "A부터 B까지"로 말한다.** D023·D022. 빠짐없음을 한 줄로 전한다.
- **대구(對句)를 쓴다.** D394 "과거도 정비하고 미래도 준비해야 합니다" · D393 "같은 듯 같지 않고 다른 듯 다르지 않습니다" · 전략 이름 "쉽고 편하게 한곳에서 / 맞춤형으로 한발 빠르게 / 사용도 관리도 체계적으로".
- **연속 장은 같은 헤드라인 + (1/3)(2/3)(3/3).** D105~D107, D405(4/6), D420(4/4). 헤드라인을 장마다 새로 짓지 않는다.
- **번호 붙은 절 제목과 키메시지를 나눈다.** "1. 연구환경 활용 체계", "8. 컨설팅지원" 같은 절 제목은 머리 띠에, 그 장이 말하려는 한 문장은 키메시지에.
- 길이는 **한 줄 18~28자**(키메시지는 모든 장이 같은 크기 한 줄). 넘치면 줄이지 두 줄로 만들지 않는다.
- 강조어는 **결과를 말하는 낱말**("빈틈없이", "정예", "25년", "안정적")에 준다. 사업명·기관명에는 주지 않는다.

## 2. 유형별 레이아웃 문법

실제 장표는 **좌 → 중 → 우 3단**이 압도적으로 많다. 왼쪽이 "상황·입력", 가운데가 "우리의 장치(플랫폼·절차·화면)", 오른쪽이 "결과·전략"이다. 유형마다 이 3단의 내용이 달라진다.

### 문제 제기·현황
- **고민하는 인물 + 흩어진 것들**: 가운데(또는 오른쪽 30%) 머리를 싸맨 인물, 주위에 기관·서류·절차가 원형·말풍선으로 흩어짐, 아래 문제 키워드 띠. → D089, D328, D329, D387
- **페르소나 3열**: 좌·중·우 세 사람 카드, 각 카드에 인물 + 그 역할이 겪는 문제 5~6개(체크리스트). → D132(v5)
- **현황 → ✕ → 불편**: 왼쪽 25% 현재 시스템, 가운데 "기능 ✕", 오른쪽 50% 도출된 불편사항. → D135
- **수치로 여는 현황**: 가운데 큰 그림(나무·지구), 좌우에 통계 수치·비율. → D004, D086
- 피할 것: 문제 목록을 번호 카드로만 늘어놓기.

### 사업 이해·목표
- **특성 → 이슈 → 전략 3단**: 왼쪽 25% 사업 특성 카드, 가운데 20% 예상 이슈(강조색), 오른쪽 55% 번호 배지 전략. → D267(v5), D137, D396
- **요구사항 매핑**: 왼쪽 30% 요구사항 목록 → 가운데 상세 → 오른쪽 고도화 방안, 점선으로 연결. → D142(v5), D145, D147
- **양쪽 인물 + 가운데 화면**: 왼쪽 이용자, 가운데 50% 통합 플랫폼 화면, 오른쪽 담당자, 양쪽에 한마디씩. 전환 장("그래서 시작합니다"). → D090(v5)
- **색 대비 두 덩어리**: 왼쪽 55% 강조색 상자(새로 생기는 것), 오른쪽 45% 파란 상자(기존 것), 위에 큰 수치 "55% / 45%". → D054(v5)

### 추진 전략·방향
- **특성 아이콘 → 플랫폼 → 전략 상자**: 왼쪽 40% 특성 3개(세로), 가운데 20% 플랫폼 표시, 오른쪽 40% 전략 3개와 과제 목록. → D337(v5), D008, D097
- **시간 3단계**: 위 40% 연도별 3단계(실린더·화살표), 가운데 타임라인, 아래 데이터·시스템·인프라 층. → D394(v5), D091, D092
- **AS-IS → TO-BE**: 왼쪽 60% 개선 경로(산·계곡 같은 높낮이로 대비), 오른쪽 40% 화면 캡처 증거와 KPI. → D405(v5), D144, D160
- **긴급 대응 흐름**: 왼쪽 25% 이슈·방안, 가운데 50% 3단계 화살표, 오른쪽 25% 전담 조직도 + 인물. → D064

### 수행 방안·절차
- **위에 3단계 흐름, 아래에 상세**: 위 40% 화살표 3~5단(구조설계→이관→품질점검), 아래 60% 좌우로 세부 구조와 검증 화면. → D420(v5), D316(v5), D496
- **절차 → 처리 → 결과 화면**: 왼쪽 20~30% Step 01~04(아이콘), 가운데 처리 흐름, 오른쪽 결과 화면·그래프. → D486(v5), D268(v5), D472(v5), D031
- **흐름도 + 증빙 표**: 왼쪽 50% 프로세스(선정→조사→정의→협약→관리), 오른쪽 50% 성과 표·보고서 캡처 + 목표 달성 배지. → D197(v5)
- 단계는 **3~5개**. 6개가 넘으면 두 줄이나 (1/2)(2/2)로.

### 구성도·아키텍처
- **사용자 → 시스템 → 외부 연계**: 왼쪽 20~30% 사용자(인물 아이콘), 가운데 50~60% 핵심 시스템(큰 상자 안 모듈 3~4개), 오른쪽 20% 외부 연계 기관, 아래 인프라(클라우드) 띠. → D177(v5), D192(v5), D416(v5), D030
- **층(레이어) 스택**: 가운데 3~4층(서비스/데이터/인프라), 왼쪽에 역할별 인물, 오른쪽에 특장점 카드. → D290(v5), D119(v5), D115
- **가로 4단계 데이터 흐름**: 연계 → 표준화 → 저장 → 통합DB, 단계마다 구성 요소. → D104(v5), D446
- 구성도는 **밀도가 높아도 된다**(거의 전부 '높음'). 대신 큰 상자 3개 안에 작은 것을 넣어 3초 안에 구조가 읽히게.

### 데이터·연계
- **기관 → 허브 → 기관**: 왼쪽 제공 기관 목록, 가운데 API/ETL·허브 구조, 오른쪽 이용 기관 목록. → D421, D163, D295
- **좌우 대조 표**: 공공 vs 민간, 현황 vs 개선. 표 두 개를 나란히. → D494(v5), D160
- **3층 구조 + 아래 활용 영역**: 위 3개 상자(메타·품질·분석), 가운데 비정형→정형 변환, 아래 활용 영역 나열. → D446(v5)

### 화면·서비스
- **실제 화면이 증거다.** 화면 캡처를 크게(전체의 55~75%), 옆 25~30%에 기능 목록. 2×2 격자가 흔하다. → D158(v5), D159(v5), D514(v5)
- **AS-IS 화면 ↔ TO-BE 화면**: 왼쪽 45% 복잡한 기존 화면, 오른쪽 55% 개선 화면, 아래 3열 개선 영역. → D144(v5)
- **대상별 3열**: 정책담당자·전문가·대국민마다 화면과 분석 카드. → D101(v5)
- **모바일 3장 → 웹 → 대시보드**: 왼쪽 35% 모바일 단계 화면, 가운데 웹, 오른쪽 데이터 시각화. → D473(v5), D474(v5)
- 화면마다 **말풍선으로 기능 설명**을 단다. → D479(v5)

### 일정·조직·인력
- **가로 타임라인 + 병렬 행**: 위에 월(M~M+7), 왼쪽 25% 활동 영역(행), 오른쪽 75% 색 막대. 마일스톤(오픈·안정화)은 강조색 핀. → D428(v5), D021, D125, D175, D223
- **조직도 + 역할 표**: 왼쪽 30~35% 지원 조직, 가운데 PM(인물 사진·프로필), 오른쪽 팀별 역할 표. → D167, D219, D251, D080
- **PM 역량 아이콘 4개**: 왼쪽 45% 역량 아이콘과 설명, 오른쪽 55% 조직 역량. → D220

### 품질·보안·테스트
- **가운데 방패, 둘레에 영역**: 가운데 큰 아이콘(방패·전문가 진단), 둘레에 관리적·물리적·기술적 3~4영역. → D033(v5), D172
- **두 프로세스 나란히**: 왼쪽 위험관리, 오른쪽 이슈관리, 가운데 우선순위 매트릭스. → D023, D249(v5), D173
- **지표 표**: 위 25% 헤드라인과 강조 메시지, 아래 75% SLA 지표 표(지표·목표·설명). 표가 주인공일 때는 꾸미지 않는다. → D072, D050

### 수행 실적·역량 · 비교·차별성
- **역사 타임라인**: 가운데 1998→현재 화살표, 위·아래에 그동안 만든 시스템 화면 8~9개, 오른쪽 끝에 올해 큰 수치. → D176(v5), D434(v5), D129
- **가운데 사람들**: 가운데 40% 실제 인력 사진(5명), 왼쪽 동기, 오른쪽 가치 카드 3개. → D027, D379

## 4. 글 밀도·부품 규칙

- **실제 장표는 촘촘하다.** 본문 장의 대부분이 밀도 '높음'이다. 글을 줄이지 말고, 큰 덩어리 3개 안에 작은 글을 넣어 구조가 먼저 읽히게 한다.
- **한 장 = 큰 덩어리 3개.** 좌·중·우 또는 위·가운데·아래. 덩어리가 5개 넘으면 장을 나눈다.
- **비율을 고르게 나누지 않는다.** 25:50:25, 30:40:30, 40:60 처럼 주인공 덩어리가 가장 넓다. 33:33:33 은 비교표일 때만.
- **카드는 3~5개, 같은 종류는 같은 크기.** 번호 배지(01~05)나 체크 표시를 붙인다. 카드 안은 제목 한 줄 + 항목 2~4줄.
- **화살표는 흐름이 있을 때만.** 왼쪽에서 오른쪽, 위에서 아래. 덩어리 사이의 큰 화살표 1~2개가 작은 화살표 여럿보다 낫다.
- **강조색은 한 장에 한 곳** — 결론 수치, 이슈 상자, 마일스톤 핀 중 하나.
- **인물은 상황을 연기한다.** 고민·설명·악수·화면 조작. 그냥 서 있는 인물 장식은 쓰지 않는다.
- **표가 주인공인 장**(SLA 지표, 일정, 데이터 현황)은 표를 크게 두고 위에 한 줄 메시지만 얹는다.
- **아래 결론 띠**는 문제 제기·전략 장에 자주 붙는다(한 줄, 네이비/코발트 바탕 흰 글).

## 5. 피할 것

참고 가치가 낮게 적힌 장의 공통점.
- 글만 가운데 놓고 배경에 흐린 사진·도구 그림을 깐 장 — 무엇을 말하는지 그림이 돕지 않는다.
- 같은 크기 카드를 번호만 바꿔 늘어놓은 장 — 흐름도 대비도 없다.
- 헤드라인이 절 제목("2. 품질관리") 그대로인 장 — 약속이나 결과가 없다.
- 덩어리 비율이 모두 같아 주인공이 없는 장.
- 화면 캡처가 작아서 글자가 안 읽히는 장 — 크게 넣거나 빼라.
- 한 장에 강조색이 세 군데 이상인 장.


## 6. 2차 전수 학습 (2026-10-04, 컨텐츠모음 542장 + 완성장표·기후플랫폼·AI시안)

한 장씩 다시 보고 적은 것. 앞의 규칙보다 이것이 우선한다.

### 색 — 파랑 4단계 + 빨강 한 곳
- **거의 모든 장이 같은 4단계 파랑**을 쓴다. ① 딥 네이비: 머리 띠·카드 머리·결론 띠·핵심 숫자 ② 코발트: 아이콘·화살표·막대·제목 바 ③ 스카이: 카드·패널 바탕 ④ 회색: 설명·캡션·테두리.
- 한 톤 파랑뿐인 장(D022·D030·D036·D112)은 가치가 2에 그친다.
- **빨강(핑크레드)은 헤드라인 속 핵심어 1~3개와 경고·차별점에만.** 도형을 빨갛게 칠하지 않는다. 차별점은 금색·빨강 "추가제안" 리본·배지(D052·D071·D541).
- **단계는 진하기로.** 단계·연차·발전은 같은 파랑의 연한 → 진한 순서(쉐브론·카드 머리·동심 반원). 오른쪽·바깥으로 갈수록 진하면 "심화"로 읽힌다(D440·D468·D478·D500·D522).

### 헤드라인
- 네이비 굵은 문장을 **가운데 정렬**하고, 큰따옴표로 감싸는 경우가 많다. 핵심어 2~3개만 빨강.
- 연속 장은 같은 헤드라인 + "(1/3)" 또는 "N단계: …". 1/2 는 표·도식, 2/2 는 실제 화면으로 짝짓는다(D487~D490·D530~D531).
- 머리 띠(높이 12~14%)는 고정 틀: 장 이름 작은 라벨 + 평가항목 | 배점 탭. 띠는 옅은 코발트 그라데이션이나 곡선·사진 띠.

### 구조
- **왼쪽 문제 → 가운데 도식 → 오른쪽 목록 → 아래 전폭 네이비 결론 띠**가 가장 흔한 뼈대. 결론 띠에는 흰·노랑 글로 결론을 한 번 더(D047 "장애 발생률 0% 달성", D057·D061·D063).
- **현재 대 목표**: 현재·기존은 회색이나 흰 패널에 작게, 목표·제안은 네이비 패널에 크게. 사이는 큰 화살표, +, 사다리꼴 확대 띠(D408·D441·D482·D528). 문제와 해결은 같은 행에 맞춰 짝짓는다(빨간 X ↔ 파랑 체크 D095, 위 AS-IS·아래 TO-BE D067, 이슈·해결·효과 3열 D068).
- **가운데 원 + 둘레 위성**(허브), **같은 틀 반복**(생애주기 띠를 장마다 되풀이하고 현재 단계만 진하게).
- **강조 겹침 장**: 앞 장을 흐리게 깔고 "사례" 카드를 띄우거나(D062·D064·D080), 전폭 띠에 한 문장만(D082). 덱 중간의 쉼표 장은 큰 낱말 하나.
- 열은 5개 이하. 스윔레인·지표 문서·인프라도를 촘촘하게 그대로 넣어 글자가 안 읽히는 장(D484·D527·D537·D538)은 피한다.

### 숫자와 증거
- **핵심 숫자는 따로 떼어 가장 크게**: 그래프 위 빨강 테두리 상자(100%↓, 157%↑), 표 위에 겹친 배지(평균 95.4점), 말풍선(60.5%→100%), 아래 큰 숫자 3개(D132), "총 8명" 합계, "28년" 월계관.
- **증거는 실물로**: 실제 화면 캡처(시안 화면에는 빨강 원 "예시" 배지), 휴대폰·모니터 목업, 뉴스 기사(D043·D131), 표창장(D051), 공문·인증서, 고객기관 로고 그리드, 인력은 사진·실명·경력 연수 카드(D081).

### 그림
- 화풍은 세 갈래를 섞는다: 반실사 3D 인물·아이콘(D090·D133·D135), 파랑 플랫 인물·선화(D055·D084), 실사·캡처. 406~542 구간은 아이콘만 51 · 플랫 선화 29 · 그림 없음 18 · 사진 합성 16 · 실사 14 · 아이소메트릭 7 · 클레이 2.
- 클레이·인물은 장의 10~15%, 한 장에 1~3명, 역할(고민·설명·조작)이 있을 때만.
- 문제 제기 장은 글보다 장면(고민하는 인물 + 말풍선, 집게 은유, 빨강 금지 아이콘).
- 전략 장은 두 글자 키워드를 육각형에 크게 + "~을 넘어 ○○으로" 대구 슬로건(D055).

### AI 시안이 자주 틀리는 것 (사람판과 비교)
- 아래 15~25%를 비운다 → 아래는 결론 띠로 채우고 빈 곳 15% 넘지 않게.
- 빨강 강조를 파랑으로 바꾼다 → 강조색은 핵심 낱말 한 곳에 유지.
- 아이콘·인물 일러를 키우고 같은 인물을 반복한다 → 카드당 아이콘 1개(약 30%), 인물 일러는 장당 최대 1개.
- 표·흐름도·숫자·고유명을 깨뜨린다 → 그런 칸은 비워 두고 서버가 그린다.
- 실제 인물·증서 사진을 일러로 바꾼다 → 실제 사진 칸은 원본 자리로 남긴다.
