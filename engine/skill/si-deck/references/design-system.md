# 디자인 시스템 — 요소별 규칙 (엔진의 근거)

사용자(2026-09-30): "키메시지는 폰트가 뭐고 색상은 뭐고 하이라이트는 무슨 색이고 위치는 어떻게 — **모든 것에 근거가 되고 규칙이 되어야 한다.**"
장표를 받으면 **먼저 이 표를 그 장표 값으로 채운 문서**(`<프로젝트>_디자인시스템.md`)를 만들고, 모든 고침·검수는 그 문서를 근거로 한다.
실물 예: `D:\powerPlus\제안서\OO시_디자인시스템.md`.

## 잠긴 값 절을 맨 위에 (OO시 회고)
하이라이트 색·머리 띠 규격·서체·그림 세트는 **견본 한 장으로 첫 판 전에 고르게** 하고 문서 맨 위 "잠긴 값"에 적는다. OO시는 하이라이트만 여섯 번 바뀌었다(D23737 → 2070E8 → 2FAC73 → EC1C68 → 2070E8 → FF3370). 아래 절의 OO시 색 값들은 그 과정의 기록이고, **최종값은 FF3370** 이다.

## 만드는 순서
1. 실측: `ds_measure`(서체·크기·색·선·그림 해상도·가이드 밖·중복) + `ds_roles`(역할별: 키메시지·머리 제목·표 머리/본문·도형 글).
2. 역할마다 **최빈값 하나**를 규칙으로 정한다. 사용자가 지목한 기준 장이 있으면 그 값이 이긴다.
3. 문서 작성(아래 목차 그대로). 예외는 쪽 번호와 이유를 적는다.
4. 검수: 규칙과 다른 것을 전수로 세어 고친다(`ds_fix`). 전 장 렌더 시트를 눈으로 본다.
5. 문서 끝에 "고친 것 / 맞는 것 / 남긴 것" 표.

## 검수에서 세는 것
소수 크기 / 7pt 미만 / 굵게 효과 / 글자 그림자 / 팔레트 밖 글자색·채움 / 가이드 밖 도형 / 150ppi 미만 그림 / 같은 장 그림 중복 / 키메시지·머리 제목의 서체·크기·색·위치 이탈 / 서체 상속 런.
테마색(tx1·bg1)은 팔레트 판정에서 뺀다. 서체 상속 런은 역할 서체로 명시한다(`ds_audit`·`ds_fix2`).
그룹 안 도형 좌표는 그룹 기준이라 "가이드 밖"에 오탐이 섞인다 — 렌더로 확인한다.

## 시안 이미지가 따로 올 때 (OO시 v0.36)
- 시안 폴더를 컨택트시트로 묶어 보고, 픽셀로 색을 잰다(하이라이트·포인트·남색·카드 면).
- 먼저 **전 장에 일괄로 옮길 수 있는 톤**(하이라이트 색, 포인트 색, 카드 선)만 적용한다. 도구 `tone_ref.sample.py`.
- 장별 재구성이 필요한 구성(수치 카드, 아래 요약 띠, 꺾쇠 흐름)은 표로 적어 보고하고 승인 뒤 장별로 한다.
- OO시 시안 값: 하이라이트 `2070E8`, 포인트 `E84078`, 카드 선 `C0D2E6`. 빨강 하이라이트는 쓰지 않는다.

## 사용 규칙 절은 반드시 넣는다 (OO시 2026-09-30)
디자인 시스템 문서에 '값'만 적으면 부족하다. 사용자: "색 개수, 블루 단계, 하이라이트, 도형 안 글자 크기와 패딩, 간격에 규칙이 있어야 한다. 하면 안 되는 것도."
- `rule_meas.py <pptx>` 로 장당 색 수, 블루 종류, 도형 안 글자 크기 분포, 도형 내 여백을 잰다.
- 문서에 넣을 절: 장당 색 개수 / 블루 4단계와 그 위 글자색 / 글자색 역할 / 도형 크기별 글자 크기 / 패딩 / 간격 / 금지 목록.
- 표마다 '규칙'과 '현재'를 나란히 적는다. 다른 곳이 고칠 후보다.
- 시안 톤을 옮길 때 면 색과 머리 띠까지 통째로 바꾸지 않는다. OO시 v0.37 은 채택되지 않았고 글자 강조색만 바꾼 v0.36 이 기준이 됐다.

## 키메시지 하이라이트 색은 고객 로고 색에서 가져온다 (2026-09-30 사용자 지시)
- OO시는 로고 심볼이 초록이라 하이라이트가 초록(2FAC73)이다. **OO시에만 해당** — 다른 장표에 그대로 쓰지 않는다.
- 새 장표는 고객 로고에서 색을 읽어 하이라이트로 제안하고, 디자인 시스템 문서에 근거(로고 색)를 적는다.
- 하이라이트 색은 한 장에서 **맨 위 키메시지 한 곳**에만 쓴다. 보조 헤드라인·본문 강조에는 쓰지 않는다. 값으로 일괄 치환하지 말고 역할로 골라 바꾼다.
- 좌우로 나란한 제목 띠가 같은 색이면 왼쪽을 한 단계 밝게 한다(`pair_tone.py`). 내용을 감싸는 상자는 폭 100% 로 두지 말고 내용 폭 + 좌우 0.2in.
- AS-IS / TO-BE 짝은 AS-IS 쪽을 회청색으로 죽여 TO-BE 가 살게 한다(좌우 띠 한 단계 차보다 더 크게).
- AS-IS·TO-BE 띠 테두리는 띠 배경색과 같게. AS-IS 회청색은 7A90B2(OO시 v0.44).
- 카드 머리 라벨은 위쪽 두 모서리만 5px 둥글게(`label_round.py`).
- 시안 캡처를 받으면 눈대중 말고 **픽셀 빈도로 색을 읽어** 팔레트 표(이전/현재/시안 실측)를 디자인 시스템에 적고, 색 값 교체와 구성 변경을 나눠 보고한다.
- 시안 톤을 옮길 땐 색 값만 바꾸지 않는다 — **테두리 유무·모서리 반지름·라벨 모양(알약)·표 합계 행**까지 같은 판에 옮겨야 시안처럼 보인다(`tone_ref4.sample.py` 참고). 키메시지 하이라이트 색은 사용자가 마지막에 정한 값이 기준(OO시: 초록 → 핑크로 번복).

## 콘텐츠 요소 톤 (OO시 v0.48, 2026-09-30)
- 짙은 채움 + 흰 글자는 구역 제목 띠에만. 콘텐츠 안 머리(TH·카드 머리)는 옅은 면 + 남색 글자, 칸은 더 옅은 면.
- 팔레트 값만 바꾸면 안 된다. 요소의 역할(띠/머리/칸/묶는 면)별로 면과 글자색을 함께 정한다.
- 흰 글자는 FFFFFF·bg1·prstClr white·흰색 그라데이션 네 형태로 들어 있다. 하나라도 빠뜨리면 옅은 면 위에 흰 글자가 남는다.
- 면 색을 바꾼 뒤에는 반드시 전 장 렌더로 "옅은 면 위 흰 글자"를 찾는다.
