# 함정 — 실제로 밟은 것 (새로 겪으면 추가)

## PowerPoint·파일 형식
- **예술 효과 원본 레이어(`a14:imgProps → hdphoto`)** 가 남으면 COM 저장 때 교체한 그림이 옛 그림으로 되돌아간다. python-pptx 단계는 멀쩡해서 늦게 발견 → 교체 도구가 레이어 제거. **파일 형식 도구와 COM 저장을 오가면 단계마다 결과를 대조.**
- `eaLnBrk="0"` 은 PowerPoint 가 무시한다. 줄은 `TextRange.Lines(i,1)` 로 읽는다. `TextFrame2…Lines()` 는 문자열을 돌려준다 → TextFrame(1) API.
- COM 열거값을 기억으로 쓰지 않는다: `AutoShapeType=148` 은 별, `msoGradientHorizontal` 은 위→아래. 도형 기하·그라데이션은 XML.
- COM 은 한글 기본 이름 "그림 N"을 "Picture N", "그룹"을 "Group" 으로 읽는다 → 이름 매칭은 둘 다. 번호까지 다른 경우도 있어 **교체 대상은 COM 으로 고유 이름(SW00)을 붙여 저장한 뒤** python-pptx 로 넘긴다(`com_rename_swap.py`).
- 지도·도식 그림 안에 그려진 작은 인물은 도형이 아니다 — 교체하려면 그림 전체가 바뀐다. 유지하고 보고.
- 새로 넣은 일러스트는 머리 띠·화살 끝·슬라이드 밖을 덮기 쉽다 → 렌더에서 띠 윗선·화살 끝 x 를 재고 다시 배치.
- 그룹 안 좌표는 그룹 좌표계 → 새 그림은 그 그룹의 `shapes.add_picture`, 위치는 COM 절대좌표로 마무리.
- COM `Characters` 인덱스가 한 글자 밀리는 경우 → 삽입 후 실제 위치를 읽어 검증.
- 글상자 3D + 흰 글자 + 좁은 자간 = 흰 얼룩.

## XML·lxml
- lxml 노드를 `id()` 로 식별 금지(프록시가 매번 새로 생긴다) → `getparent()` 체인.
- 그라데이션 스톱까지 스냅하면 밴드가 평면이 된다.

## 판정·검수
- 자동 감사 = 보정 후보. s12 카드 "중심 0.19in 어긋남"은 설명 상자가 카드 밖으로 뻗은 오탐 — 보정하니 제목이 설명을 덮었다.
- 같은 검사식이 레이아웃마다 맞기도 틀리기도 한다 → 영구 제외 목록.
- 마킹 번호를 아이콘 위에 찍으면 마킹이 아이콘을 가려 숫자 뱃지로 오판 → 크롭 시트.
- 흰 글자 판정에 밝은 칸(≥0.8)을 포함하면 연한 칸이 중간 파랑으로 칠해진다.
- 크롭 비교는 두 이미지의 같은 좌표 — 위치가 어긋나면 멀쩡한 걸 고친다.
- 가이드 측정은 머리말 그림자·가장자리 장식을 빼야 한다.
- `audit_checklist.py` 07a/07b(선 0.75/1pt·30%)는 착수보고 전용 규칙.

## 규칙 설계
- **도식을 한 건씩 따로 재제작하면 도식끼리 색 역할이 갈린다**(OO시 v0.6: 시작=진한 남색/보라 네이비/연한 하늘 제각각, 판단 마름모=흰 바탕/파랑 테두리/진한 채움 제각각). 역할→색 표를 가이드에 먼저 정하고 재제작·통일을 그 표로.
- 정렬 규칙은 이동량 상한과 함께. 정렬 대상보다 "정렬하면 안 되는 구조"(스택)를 먼저 가른다.
- 크기 비슷한 것만 묶어 덩어리감을 맞춘다. 인물은 구도가 다르면 크기를 맞춰도 어긋난다.
- 크기를 줄여 줄 수를 맞추면 형제끼리 톤이 갈린다 → 고아 줄은 줄바꿈으로, 크기는 형제 전체 한 값.
- 종류→자산 1:1 매핑은 한 장 안 중복을 만든다 → 종류당 3개.
- 표준 스케일 배열로 크기를 스냅하면 빠진 정수까지 내려간다 → "정수 유지, 소수만 내림".
- 굵기로 서체 역할을 가르지 않는다.
- 자간을 풀면 줄이 는다 → 바로 fit_breaks.
- 지시 마커를 글자로만 찾으면 본문까지 지운다.
- 교체 대상은 목록이 아니라 렌더에 보이는 것(z-order) 기준.

- **사용자가 보여 준 화면 색이 파일 색과 다르면, 열린 PowerPoint 에서 고치고 저장 안 한 것이다**(OO시 34p: 파일 EB696D, 화면 F71148, `~$` 잠금 파일 존재, 빨간 물결 밑줄). 파일을 다시 열어 작업하면 그 수정이 날아간다 → COM `GetObject` 로 열린 문서에서 기준값을 읽고, 그 문서에 적용한 뒤 `SaveCopyAs` 로 새 판 저장. 픽셀로 화면 색을 먼저 재서 파일과 대조할 것.

## 환경
- `python` = 스토어 스텁. `python -` 인라인은 REPL 로 멈춘다 → 절대경로 파이썬 + 스크립트 파일.
- 스크래치 스크립트를 `inspect.py` 같은 표준 모듈명으로 짓지 않는다(numpy·lxml import 가 깨졌다).
- heredoc·`node -e`·셸 인자에서 백슬래시가 한 겹 벗겨진다(`\n`→실제 줄바꿈). 정규식·`\n` 든 명세는 Edit/Write 도구로.
- 셸 heredoc 에 `"\r"` 을 넣으면 실제 CR 이 박힌다 → `chr(13)`.
- 사용자가 PowerPoint 로 연 파일은 잠김(`~$` 파일) → 새 판 이름으로 저장.
- git-bash curl 로 한글 쿼리를 보내면 0건 → 서버에서 `curl localhost`.
- 빈 환경변수로 `cd $경로` 하면 홈에 풀린다(`FTP_REMOTE_PATH`).


## 교체 그림이 키우면 깨진다 — set_swap 400px 캔버스 (OO시 v0.21, 2026-09-30)
- `set_swap.py` 가 새 그림을 옛 그림 캔버스(400px 상한)에 맞춰 줄여 넣었다. 사용자가 장표에서 키우자 전부 깨짐. → 상한 1200 으로 올리고, 이미 들어간 것은 `pic_hires.py` 로 원본(잉크 크롭) 재삽입(보이는 영역·반전·자르기는 XML 로 유지).
- 원칙: **파워플러스 자산은 원본 크기 등록, 장표엔 원본 그대로** — 축소는 썸네일만.

## 자동 번호 목록은 텍스트에 번호가 없다 (OO시 v0.23)
- "1)~6) 항목만"을 정규식 `^\d\)` 로 찾으면 0건 — PowerPoint 자동 번호는 `Text` 에 안 실린다. `Paragraphs(k).IndentLevel`(또는 XML `a:buAutoNum`)로 단계를 가른다.

## 인물 그림 반전 전에 글자가 있는지 본다 (OO시 v0.24)
- "인물은 안쪽을 본다" 규칙으로 반전했더니 그림 속 before/after 글자가 거울상이 됐다(s8). 반전은 글자 없는 그림만 — 있으면 세트에서 반대 방향 자산으로 교체.
- 머리·본체 카드 사이 흰 쐐기는 본체 roundRect 의 위 모서리 — round2SameRect 180° 회전 + bodyPr rot 로 아래만 둥글게.

## ⭐ 그림이 깨지는 진짜 원인 = PowerPoint 저장 시 이미지 압축 (OO시 v0.26)
- 원본(550px)을 넣어도 PowerPoint 에서 저장하면 **표시 크기 × 220ppi** 로 다시 줄인다(0.5in → 110px). v0.21 에서 재삽입하고도 재발한 이유. `set_swap` 캔버스는 부차 원인이었다.
- 파일: `p14:defaultImageDpi val=32767`(압축 안 함). PC: `HKCU\Software\Microsoft\Office.0\PowerPoint\Options\AutomaticPictureCompressionDefault=0`. COM `SaveCopyAs` 도 같은 압축을 탄다 — 기록이 먼저.
- 편집 화면 가이드 선은 `presentation.xml` 의 `p15:sldGuideLst`. viewProps 만 고치면 PowerPoint 가 새 선을 하나 더 만들고 옛 선은 남는다.

## python-pptx 는 런 텍스트의 \v 를 줄바꿈으로 안 바꾼다 (OO시 v0.69)
`r.text = "앞\v뒤"` 가 화면에 `_x000B_` 글자로 찍힌다(python-pptx 가 제어문자를 이스케이프). 줄바꿈은 `<a:br/>` 요소를 직접 — `linebreak_mark.py`(런에 `_x000B_` 표시를 넣고 돌리면 br 로 쪼갬).

## 슬라이드 밖 노랑 메모를 '잔여 도형'으로 지웠다 (OO시 v0.68~v0.69)
"슬라이드 밖 도형 삭제"로 28쪽 메모(웃는 얼굴 40), 5쪽 메모를 지웠다 — 0절 원칙 2 위반. 밖에 있는 건 대부분 `memo_offslide` 로 옮긴 기획 메모다. **밖 도형은 지우지 말고 목록만 보고**, 지우려면 노랑·스마일 여부부터 확인. 이전 판에서 요소를 deepcopy 해 복원했다.
원본 대조 에이전트가 'PDF 텍스트에 남는다'며 메모 삭제를 권해도 따르지 않는다 → 납품 PDF 직전에만 사용자 확인 후.

## 명령 앞에 `py -` 를 붙이면 입력 대기로 멈춘다 (재발)
heredoc 없이 `py -` 만 있으면 REPL 이 stdin 을 기다려 2분 타임아웃 → 뒤 명령이 전부 실행 안 됨. 여러 파일에 붙이는 글은 스크립트 파일로.

## 한 번 나온 오류는 기본 규칙 원천에 남긴다 (2026-10-12)
목록·규칙·막는 장치의 원천은 powerplus-platform `engine/known_errors.json` 하나다(사람용 판: `docs/장표-기본규칙-오류체크리스트.md`).
웹 엔진은 이 목록을 다듬기 지시문의 '기본 규칙'으로 싣는다. 게이트(sizeguard·cardfit·textlines)가 다시 잡으면 개선 체크리스트 `known:<slug>` 가 '다시 걸림'으로 바뀐다.
새 오류를 고쳤으면 여기에 적는 것과 함께 그 json 에 한 줄 + 회귀 시험(`engine/tests/test_known.py`)을 추가한다. 배포 스크립트가 시험 실패 시 올리지 않는다.
